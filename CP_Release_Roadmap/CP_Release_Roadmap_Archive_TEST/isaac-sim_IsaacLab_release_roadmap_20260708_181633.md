# isaac-sim/IsaacLab Release Roadmap

- 仓库: `isaac-sim/IsaacLab`
- 统计窗口: 最近一年
- 最新版本: v3.0.0-beta2.patch1 (2026-07-02 12:21:18 CST)
- 纳入统计的最早版本: v2.1.1 (2025-07-30 20:59:44 CST)
- 版本概况: 最近一年共 9 个版本，其中正式版 6 个、预发布版 3 个
- 详细证据索引: `isaac-sim_IsaacLab_release_roadmap_reference.md`

## 核心判断

- **Isaac Lab 在过去一年完成了从成熟稳定版到架构级重构的跨越。** 从 v2.1.1 到 v3.0.0-beta2.patch1，产品经历了两个截然不同的阶段：上半年（v2.1.1 至 v2.3.2）以功能增量和生态扩展为主，下半年（v3.0.0-beta 系列）则引入了多后端物理引擎、可插拔渲染器、无 Kit 运行模式等根本性架构变革。对于产品经理而言，这意味着现有基于 2.x 版本构建的工作流在迁移到 3.0 时需要投入显著的适配成本。

- **3.0 系列的核心战略是打破对 Isaac Sim 的强依赖，实现仿真后端的解耦与多样化。** 通过工厂模式的多后端架构，Isaac Lab 现在支持 PhysX（默认）、Newton（基于 MuJoCo-Warp）等多种物理后端，并允许在无 Isaac Sim 的 Kit-less 模式下运行。这一变化直接扩展了产品的目标用户群：从必须部署完整 Omniverse 生态的团队，扩展到更广泛的机器人学习研究者，尤其是那些偏好轻量级、高吞吐训练管线的用户。

- **Newton 物理后端是 3.0 版本最具差异化的能力，但尚处于 Beta 阶段。** Newton 后端支持 CUDA 图加速、多种求解器（MJWarp、XPBD、Featherstone），并提供了 20+ 环境的预设配置。然而，官方明确标注了性能回退和破坏性变更的可能性，且 Newton 的传感器支持（如射线投射、IMU）仍在完善中。对于追求稳定性的生产级项目，建议继续使用 PhysX 后端，同时将 Newton 作为高吞吐训练场景的评估选项。

- **2.x 系列的最后一个版本 v2.3.2 是功能最丰富的稳定基线，适合作为长期支持版本。** 该版本引入了多旋翼无人机支持、多网格射线投射器、视觉触觉传感器等重大新功能，并明确声明这是 main 分支的最终版本，后续开发已转向 develop 分支。如果团队当前无法承担 3.0 的迁移成本，v2.3.2 是一个合理的冻结点。

## 产品演进主线

- **从单一后端到多后端解耦架构。** 这是过去一年最根本的产品变化。v2.x 时代，Isaac Lab 紧密绑定 Isaac Sim 和 PhysX 引擎。v3.0.0-beta 引入了工厂模式，将资产类（如 Articulation、RigidObject）和传感器类抽象为基类，后端实现放在独立的扩展包中（isaaclab_physx、isaaclab_newton）。这意味着用户代码无需修改即可在不同后端间切换，但底层配置（如物理材质、求解器参数）需要按后端调整。这一架构为未来支持更多物理引擎（如 OVPhysX）铺平了道路。

- **Kit-less 运行模式与轻量化部署。** v3.0.0-beta 引入的 isaaclab_newton 扩展允许在完全不启动 Isaac Sim 的情况下运行仿真环境。这对于大规模并行训练、云端部署、以及资源受限的边缘设备场景至关重要。Kit-less 模式结合新的 `--viz` 命令行标志（支持 kit、newton、rerun、viser 四种可视化后端），使用户可以根据场景灵活选择渲染方案，甚至完全关闭可视化以最大化训练吞吐。

- **模仿学习与灵巧操作管线的持续深化。** 从 v2.2.0 开始，产品在模仿学习方向投入显著。v2.2.0 引入了 FORGE 和 AutoMate 等接触丰富的操作任务；v2.3.0 推出了 DexSuite（灵巧操作环境套件）、SkillGen（基于 cuRobo 的技能级数据生成）以及 G1 人形机器人的全身运动规划管线。这些能力使 Isaac Lab 从单纯的强化学习平台，逐步演变为覆盖数据生成、策略训练、策略部署的全链路机器人学习平台。

- **平台兼容性与开发者体验的持续提升。** 过去一年，产品完成了 Python 3.10 到 3.12 的升级、PyTorch 2.7.0 到 2.10.0 的更新、CUDA 12.8 及 13.0 的支持、以及 Ubuntu 20.04 的淘汰（转向 22.04/24.04）。v2.2.0 引入了 Fabric 场景委托和内存阶段化以提升渲染和场景创建性能。v3.0.0-beta2 进一步改进了安装流程、CI 管道和文档，并提供了自动化的迁移工具。这些变化降低了新用户的入门门槛，但也意味着旧环境（如 Ubuntu 20.04、Python 3.10）的用户需要规划升级。

## 版本演进解读

### v3.0.0-beta2.patch1（2026-07-02）

- 这是一个针对 v3.0.0-beta2 的小型补丁，主要更新了 Isaac Sim 依赖至 6.0.1 版本。Isaac Sim 6.0.1 修复了 NuRec 工作流中的流式传输崩溃问题，并增加了对稀疏像素高斯（SPG）渲染场景的遥操作支持。
- 同时修复了 h5py 版本兼容性（要求 >=3.16.0）和 Docker 镜像的兼容性问题。对于使用 NuRec 或流式渲染的用户，此补丁是必要的升级。

### v3.0.0-beta2（2026-06-17）

- 这是 3.0 Beta 系列的第二个版本，重点在于多后端架构的稳定化和功能完善。Newton 后端新增了射线投射器、帧变换器、IMU/PVA 传感器、接触传感器、关节扳手传感器、可变形体支持以及 VBD 耦合支持。同时为四足和双足机器人添加了 Newton 粗糙地形运动预设。
- 多后端架构在 PhysX、Newton、OVPhysX、Isaac RTX、OVRTX 和无 Kit 执行路径上得到了硬化，改进了后端选择逻辑、场景数据路由、克隆计划处理、传感器重置行为以及运行时兼容性检查。当请求不支持的物理/渲染/可视化组合时，现在会给出更清晰的错误提示。
- 迁移成本方面，此版本仍为 Beta 版本，官方明确警告 develop 分支可能继续引入破坏性变更。建议仅用于评估和实验，不适合生产部署。

### v3.0.0-beta（2026-03-17）

- 这是 Isaac Lab 3.0 的首个 Beta 版本，引入了根本性的架构重构。核心变化包括：工厂模式的多后端物理架构（PhysX 和 Newton）、可插拔可视化框架（支持 kit、newton、rerun、viser 四种后端）、Warp 原生数据管线（状态数据直接返回 Warp 数组以减少 CPU-GPU 拷贝）、以及无 Kit 安装模式。
- 破坏性变更较多：`--headless` 标志被 `--viz` 替代；所有四元数统一为 XYZW 顺序；传感器数据返回类型从 torch.Tensor 变为 warp.array；URDF/MJCF 导入器为 Isaac Sim 6.0 重写；RL 训练入口点统一为 `isaaclab.sh train --rl_library <lib>`。官方提供了迁移指南和自动化工具。
- 已知限制包括：性能回退、Windows 支持尚未就绪、pip wheels 尚未发布。此版本仅支持 Ubuntu。

### v2.3.2（2026-02-03）

- 这是 2.x 系列的最终版本，也是功能最丰富的稳定版本。新增了多旋翼无人机支持（含推进器执行器和 ARL 无人机任务）、多网格射线投射器（支持动态网格追踪）、视觉触觉传感器（含形状感知示例）、Haply 设备集成、以及 OpenArm 环境。
- 核心 API 方面，`set_external_force_and_torque()` 方法被弃用，替换为新的可组合扳手系统。此版本明确声明是 main 分支的最终版本，后续开发将转向 develop 分支。
- 对于需要稳定基线且短期内不计划迁移到 3.0 的团队，此版本是最佳选择。

### v2.3.1（2025-12-05）

- 这是一个小型补丁版本，修复了影响用户工作流的关键问题。主要修复包括：终止日志记录行为变更（`get_done_term` 现在返回当前步数值而非上一 episode 值）；URDF 导入器更新至 2.4.31 以恢复对 merge-joints 标志的支持（该标志在 Isaac Sim 5.1 中被移除）。
- 对于使用 URDF 导入或依赖终止日志记录的用户，此补丁是必要的。

### v2.3.0（2025-10-29）

- 此版本基于 Isaac Sim 5.1，重点增强了灵巧操作、遥操作和模仿学习工作流。引入了 DexSuite（含两个基于 Kuka 臂和 Allegro 手的灵巧操作环境，支持自动域随机化和群体训练）、SurfaceGripper 的 Manager 工作流支持、以及 SkillGen（基于 cuRobo 的 GPU 加速运动规划和技能级数据生成）。
- 新增了 G1 人形机器人环境，结合了基于强化学习的运动控制和逆运动学操作。完整的机器人导航栈被集成到模仿学习管线中。
- 注意：cuRobo 集成具有专有许可条款，使用前需仔细审查许可协议。

### v2.2.1（2025-08-30）

- 这是一个功能增强的补丁版本。ContactSensor 新增了接触点位置报告功能；Pink IK 控制器增加了零空间姿态控制；新增了 RSL-RL 对称性示例（Cartpole 和 ANYmal 运动）。
- 基础设施方面，禁用了头部渲染和头部渲染应用的速率限制，并将分析器后端默认设置为 NVTX。这些改进对训练吞吐和调试体验有积极影响。

### v2.2.0（2025-08-08）

- 此版本基于 Isaac Sim 5.0，同时向后兼容 Isaac Sim 4.5。核心增强包括：基于最新 PhysX API 的关节摩擦建模、空间肌腱支持、改进的表面夹爪交互。新增了 GR1 模仿学习环境、FORGE 和 AutoMate 接触丰富操作任务。
- 性能方面，引入了内存阶段化和 Fabric 克隆以加速场景创建，新增了 OVD 记录器用于大规模场景的 GPU 动画录制，以及 FSD（Fabric 场景委托）以提升渲染速度。
- 平台方面，Python 版本从 3.10 升级到 3.11，正式放弃对 Ubuntu 20.04 的支持。原生直播流支持被移除，WebRTC 流媒体成为替代方案。

### v2.1.1（2025-07-30）

- 此版本兼容 Isaac Sim 4.5，是过去一年最早记录的版本。新增了资产接口（如设置外部力和扭矩的位置参数、关节扳手数据）、传感器接口（FrameTransformer 可视化改进）、以及 MDP 项（身体姿态、关节力观测等）。
- 重要破坏性变更：`enable_stabilization` 标志默认值改为 False，因为 PhysX 求解器已改进，不再需要非物理启发式稳定化。此变更可能影响接触力报告的准确性，用户需注意验证。
- 此版本未提供 Docker 镜像或 pip 包，安装方式受限。

## 采用与规划提示

- **现有 2.x 用户应评估迁移窗口。** 如果当前项目依赖 2.x 的稳定 API 且没有立即使用多后端或 Kit-less 模式的需求，建议以 v2.3.2 作为长期支持基线。3.0 的迁移成本较高，涉及 API 重命名、配置结构调整、以及可能的性能回归。建议在 3.0 正式版（非 Beta）发布后再规划迁移，届时破坏性变更应已收敛。

- **新项目应直接评估 3.0 Beta 系列。** 如果项目处于早期阶段，且对多后端物理（尤其是 Newton 的高吞吐训练）、Kit-less 部署、或可插拔可视化有明确需求，可以从 v3.0.0-beta2 开始评估。但需接受 Beta 阶段的不稳定性，并预留调试时间。建议关注 develop 分支的更新频率和破坏性变更的收敛趋势。

- **关注 Newton 后端的成熟度与生态建设。** Newton 是 3.0 最具战略价值的差异化能力，但目前传感器支持（如射线投射、IMU）仍在完善中，且官方未提供性能基准数据。建议在内部建立 Newton 与 PhysX 的对比评估流程，重点关注训练吞吐、仿真保真度、以及传感器数据一致性。如果 Newton 在后续版本中达到与 PhysX 相当的功能覆盖，将显著改变产品的竞争格局。

- **生态系统依赖风险需纳入规划。** 多个关键功能（如 SkillGen 的 cuRobo 集成）具有专有许可条款，可能限制商业使用或分发。同时，Omniverse Launcher 和 Nucleus 将于 2025 年 10 月后停止支持，依赖这些组件的用户需规划迁移到 Enterprise Nucleus Server 或完全转向 Kit-less 模式。建议在技术选型时明确记录所有第三方依赖的许可条款和生命周期状态。
