# NVIDIA/warp Release Roadmap

- 仓库: `NVIDIA/warp`
- 统计窗口: 最近一年
- 最新版本: v1.15.0 (2026-07-08 06:40:23 CST)
- 纳入统计的最早版本: v1.8.1 (2025-08-02 01:41:44 CST)
- 版本概况: 最近一年共 13 个版本，其中正式版 12 个、预发布版 1 个
- 详细证据索引: `NVIDIA_warp_release_roadmap_reference.md`

## 核心判断

- **Warp 正在从单一 GPU 计算库演变为可移植、可序列化的仿真运行时。** 过去一年，v1.13 引入的实验性图捕获序列化（`.wrp` 格式）和 CPU 回放是架构层面的转折点。v1.14 和 v1.15 持续扩展了可捕获的操作集（包括反向传播、平铺内核、结构化参数），使得仿真管线可以跨进程、跨语言（Python / C++）保存和加载，不再绑定于单一 GPU 会话。这对需要确定性复现、离线调试或部署到异构环境的团队有直接价值。

- **确定性执行和内存管理成为差异化竞争力。** v1.15 新增的确定性原子执行模式（`RUN_TO_RUN` 和 `GPU_TO_GPU`）直接服务于仿真验证和回归测试场景，虽然性能有取舍，但填补了 GPU 仿真中结果不可复现的关键空白。同时，v1.13 引入的可插拔 CUDA 分配器（RMM 集成）和 v1.15 的 CUDA managed-memory 支持，让 Warp 能够与 PyTorch、CuPy 等框架共享 GPU 内存池，降低多框架共存时的显存浪费。

- **物理仿真模块正式剥离，生态重心转向 Newton 和 JAX。** v1.10 移除了 `warp.sim` 模块（自 v1.8 起弃用），由独立的 Newton 物理引擎接替。与此同时，Warp 持续强化与 JAX 的互操作：v1.10 加入实验性 JAX 自动微分支持，v1.12 支持 `jax.vmap`，v1.14 稳定了 JAX 集成 API。这表明 NVIDIA 正在将 Warp 定位为底层计算和微分框架，而非完整的物理引擎。

- **API 清理和平台支持收紧，迁移成本集中在 v1.11–v1.13 区间。** 过去一年，Warp 完成了大规模内部 API 清理（`warp._src` 子包、弃用转发 shim、移除私有路径），Python 3.9 支持在 v1.13 终止，CUDA 11 支持在 v1.9 终止，Omniverse Kit 扩展在 v1.12.1 移除。这些变更对长期用户有一次性迁移成本，但换来了更清晰的公共 API 边界和更低的维护负担。

## 产品演进主线

- **从 GPU 专属到 CPU+GPU 双后端 + 可移植图捕获。** 早期 Warp 主要面向 CUDA GPU 加速。过去一年，CPU 后端从基本可用演进到支持图捕获、回放和序列化。v1.13 的 `.wrp` 格式和 APIC 序列化是核心基础设施，v1.14 扩展了可捕获的操作（反向传播、平铺内核、`wp.indexedarray`），v1.15 进一步支持 CPU 图和已保存 CUDA 图的回放。这使得仿真工作流可以脱离 GPU 环境进行调试、验证和部署。

- **仿真可复现性和调试能力从零到一。** v1.15 的确定性执行模式是过去一年最重要的仿真质量特性。它通过重写原子操作（累加、槽分配）为确定性的排序-规约或计数-扫描-写入模式，实现了跨运行和跨 GPU 架构的位精确结果。虽然不支持所有原子模式（如 `atomic_cas`、`atomic_exch`），且性能影响因场景而异，但它为回归测试、CI 验证和学术可复现性提供了基础能力。

- **平铺（Tile）编程模型持续成熟。** 从 v1.9 到 v1.15，平铺操作从基础矩阵运算扩展到 FFT（v1.12 支持可微 FFT）、元素级算术运算符（v1.12）、struct 支持（v1.15）、以及大量正确性修复（v1.11.1、v1.12.1）。平铺模型允许在 CUDA 线程块级别进行协作计算，对于需要高吞吐的仿真内核（如 FEM、粒子系统）至关重要。

- **生态整合：JAX 深化、Newton 接替、PyTorch 共存。** Warp 在 JAX 方向投入显著：v1.10 的实验性自动微分、v1.12 的 `jax.vmap` 支持、v1.14 的稳定 API。同时，`warp.sim` 的移除和 Newton 的独立发展意味着物理仿真用户需要迁移。与 PyTorch 的互操作通过 RMM 共享内存池（v1.13）和纹理互操作（v1.12）得到加强，但 Warp 并未试图成为 PyTorch 的替代品，而是作为可微分计算的后端存在。

## 版本演进解读

### v1.15.0（2026-07-08）

- **确定性原子执行**：新增 `wp.DeterministicMode.RUN_TO_RUN`（同架构位精确）和 `GPU_TO_GPU`（跨架构保守路径）。支持模式 1（累加/减/最小/最大）和模式 2（槽分配）。不支持 `atomic_cas`、`atomic_exch` 和平铺原子操作。性能影响因竞争程度而异——高竞争场景可能更快，稀疏场景通常变慢。用户需在模块级别或内核级别启用。
- **引用参数和函数参数**：`wp.ref[T]` 允许用户定义函数直接修改调用者持有的存储，消除了返回值再赋值的模式。这对需要更新多个值的辅助函数（如物理约束求解）有实际价值。
- **CUDA managed-memory 分配**：支持通过 `device="cuda:0"` 分配统一内存，简化 CPU-GPU 数据共享。同时新增 mipmapped 纹理支持。
- **迁移注意**：确定性模式是实验性特性，API 可能变化。纹理 API 同样标记为实验性。

### v1.14.0（2026-06-01）

- **API 捕获扩展**：CPU 图捕获现在支持反向传播（`wp.Tape().backward()`）、`wp.launch_tiled()` 内核、任意大小的标量参数。`.wrp` 序列化格式支持包含数组的 `@wp.struct` 参数和 `wp.indexedarray` 参数。APIC 格式版本升级到 v10，v1.13 保存的文件需要重新捕获。
- **多环境 FEM**：支持批量仿真的多环境有限元模拟，适用于需要同时模拟多个独立物理场景的机器人训练或材料测试。
- **可重用和批量线性求解器**：线性求解器现在可以重用和批量化，减少重复分配开销。可插拔日志系统允许用户控制日志级别和输出。
- **迁移注意**：C/C++ APIC 句柄声明需要更新为显式指针（如 `APICState*`）。FEM 构造函数中 `requires_grad`、`device`、`temporary_store` 的位置参数签名已更改。

### v1.13.0（2026-05-04）

- **图捕获序列化和 CPU 回放（实验性）**：这是架构级新能力。`wp.capture_begin(apic=True)` / `wp.capture_end()` 记录的操作可以保存为 `.wrp` 文件，并通过 `wp.capture_load()` 在 Python 或独立 C++ 中回放。CPU 图捕获首次可用。`wp.handle`（`uint64` 别名）支持跨保存/加载携带网格句柄。
- **cuBQL BVH 后端**：为 `wp.Mesh` 提供基于 cuBQL 的 BVH 构建器，在射线密集的网格查询场景中通常比现有 SAH 构建器更快。一个 RTX 4090 上的渲染基准测试显示仿真时间从 1.41 秒降至 0.98 秒。效果因场景而异，建议用户自行基准测试。
- **可插拔 CUDA 分配器和 RMM 集成**：`wp.set_cuda_allocator(wp.utils.AllocatorRmm())` 允许 Warp 与 PyTorch、CuPy 共享 RAPIDS 内存池。`wp.ScopedMemoryTracker` 提供带调用站点的内存跟踪。
- **`wp.bfloat16` 类型**：新增 16 位脑浮点类型，适用于需要降低内存占用的场景。
- **迁移注意**：AOT 编译的 CPU 模块现在包含主机 ISA 哈希，跨主机加载不兼容的二进制文件会崩溃。`wp.config.cpu_compiler_flags = ""` 可回退到可移植基线。私有 API 转发 shim 已移除，使用 `warp._src` 路径的代码将报错。

### v1.12.1（2026-04-06）

- **平铺正确性修复**：修复了跨设备 `block_dim` 错误、`tile_matmul` 和 `tile_fft` 忽略 `enable_backward`、以及 `@wp.func` 中平铺参数编译失败的问题。平铺参数现在按引用传递。
- **Omniverse Kit 扩展移除**：仓库中不再包含 Omniverse Kit 扩展。这简化了 Warp 核心仓库的维护，但使用 Omniverse 集成的用户需要寻找替代方案。
- **Python 3.9 弃用确认**：v1.13 将移除 Python 3.9 支持。私有 API 弃用警告将在 v1.13 移除。
- **新增示例**：可微 2D Navier-Stokes 优化示例和三个 `warp.fem` 示例。

### v1.12.0（2026-03-07）

- **硬件加速纹理采样（实验性）**：`wp.Texture1D`/`2D`/`3D` 利用 CUDA 纹理内存进行硬件加速插值，适用于渲染、体积采样、SDF 查询和仿真查找表。CPU 上有软件回退。纹理对象新增 `copy_from()` / `copy_to()` 方法，旧方法已弃用。
- **平铺编程扩展**：元素级算术运算符（`*`、`/`）、可微 FFT（`wp.tile_fft` 支持 N>=2 维度的平铺）、以及 `tile_stack`、`tile_axpy` 等新原语。
- **JAX 互操作增强**：支持 `jax.vmap`，允许 JAX 的向量化映射应用于 Warp 内核。`jax_callable` 新增 `force_ffi` 参数。
- **下标风格类型提示**：`wp.array[dtype]` 和 `wp.tile[dtype, shape]` 语法，改善 IDE 集成。
- **迁移注意**：Python 3.9 弃用警告已添加。隐式标量到复合类型的转换已弃用。`wp.matrix()` 从行向量构造矩阵的支持已移除。

### v1.11.1（2026-02-04）

- **平铺修复**：修复 `tile_matmul` 因未初始化输出内存产生 NaN、标量常量与向量/矩阵类型的乘法错误、以及 `tile_map` 不支持标量/向量/矩阵参数。
- **CUDA 图内存优化**：修复多临时分配场景下内存无法重用的问题（例如三个 1GB 顺序分配消耗 3GB 而非 1GB）。
- **开发者体验**：修复 `@wp.func` 在 Pyright/Pylance 中显示泛型 `_Wrapped` 类型的问题。IDE 自动补全存根多项修复。
- **新增**：`wp.grad()` 示例（粒子排斥）、分组感知的 BVH/网格查询、平铺线性代数原地变体以减少共享内存使用。

### v1.11.0（2026-01-02）

- **分组感知空间查询**：`wp.Bvh` 和 `wp.Mesh` 支持 `groups` 参数，允许在单一加速结构中包含多个独立环境（世界），查询时只遍历指定世界的图元。这对多世界仿真（如机器人训练中的并行环境）至关重要。
- **JIT 编译管理**：`wp.force_load()` 提供更细粒度的模块编译控制。预编译头支持（CUDA 12.8+）可减少内核编译时间。并行模块编译和加载。
- **`wp.grad()` 扩展**：新增 `wp.grad()` 函数，允许在 kernel 内部直接获取标量输出的梯度，简化自定义微分逻辑。
- **API 清理**：内部 API 访问（如 `wp.context`）发出弃用警告，将在 v1.13 移除。文档重组，公共 API 边界明确。
- **迁移注意**：设置 `wp.config.verbose_warnings = True` 可获取弃用警告的源位置。`wp.force_load()` 无参数时会编译所有模块，可能耗时很长。

### v1.10.1（2025-12-01）

- **错误修复**：修复 `module="unique"` 内核重用、kernel 内 `wp.zeros()` 数组的 `.ptr` 访问和索引、自定义梯度函数编译顺序、FEM `TemporaryStore` 无效读取等问题。
- **弃用**：`jax_callable()` 的 `graph_compatible` 参数弃用，改用 `graph_mode` 枚举（`GraphMode.JAX` / `WARP` / `NONE`）。
- **平台通知**：Python 3.8 支持将在 v1.11 移除。PyPI 预构建 wheel 将从 CUDA 12.8 切换到 12.9。

### v1.10.0（2025-11-02）

- **`warp.sim` 模块移除**：这是最重要的架构变更。`warp.sim` 自 v1.8 起弃用，由独立的 Newton 物理引擎接替。使用 `warp.sim` 的代码需要迁移到 Newton。
- **JAX 自动微分（实验性）**：Warp 内核现在可以参与 JAX 的 `jax.grad()` 工作流。支持单输出和多输出内核，标量输入自动视为静态。`jax.pmap()` 多设备支持。
- **性能提升**：Python 作用域内置函数调用速度提升最高 70 倍（通过 `lru_cache` 缓存重载解析）。BVH 支持原地重建和可配置叶子大小（默认从 4 改为 1）。
- **内部代码重组**：实现代码移至 `warp._src` 子包，公共 API 边界更清晰。
- **迁移注意**：向内置函数传递列表/元组等非 Warp 数组参数的支持已移除。Intel macOS（x86_64）支持已移除。

### v1.9.1（2025-10-01）

- **GPU 架构兼容性修复**：恢复对 Maxwell、Pascal、Volta 等旧架构的支持（v1.9.0 预构建 wheel 意外丢失）。
- **平铺稳定性**：修复共享平铺的内存管理问题（双重释放、内存泄漏）。`wp.copy()` 和 `wp.where()` 现在支持平铺并计算正确梯度。
- **ARM CPU 已知问题**：Linux ARM 系统（Jetson、Grace Hopper）上的 CPU kernel 可能段错误，计划 v1.10 修复。
- **弃用提醒**：`warp.sim` 将在 v1.10 移除。

### v1.9.0（2025-09-05）

- **可微 Marching Cubes**：完全用 Warp 重写，替代原生 CUDA C++ 实现，支持 CPU 和 GPU，修复了长期存在的 off-by-one 错误。适用于从 3D 标量场提取三角形网格的可微管线。
- **AOT 编译函数**：`wp.compile_aot_module()` 和 `wp.load_aot_module()` 支持分发预编译模块，`strip_hash=True` 可移除哈希使模块名可预测。
- **CUDA 13 支持**：PyPI wheel 继续使用 CUDA 12.8 构建以提供过渡期，但源码构建支持 CUDA 13。
- **图可捕获线性求解器**：`warp.optim.linear` 中的 CG、BiCGSTAB、GMRES 求解器支持 CUDA 图捕获，通过 `wp.capture_while()` 实现设备端收敛检查。

### v1.9.0rc1（2025-08-20）

- 仅作为 Isaac Lab 测试的发布候选版本，无独立用户可见特性。

### v1.8.1（2025-08-02）

- **MuJoCo MJX 适配**：为支持 MuJoCo MJX 物理引擎采用 Warp，`jax_experimental` 模块新增 `graph_mode` 参数（`GraphMode.WARP`），支持包含条件节点的图捕获。
- **CUDA 11 最终支持**：这是最后一个支持 CUDA 11.x 的版本。v1.9.0 起需要 CUDA 12.x 或更新版本。
- **修复**：修复 `tape.zero()` 在嵌套结构体中梯度重置、`div(scalar, vec)` 等错误伴随、CUDA 模块在条件图节点中过早卸载等问题。

## 采用与规划提示

- **当前采用窗口（2026 年中）**：v1.15 是过去一年功能最完整的版本，确定性执行和 managed-memory 对仿真质量和内存管理有直接价值。如果团队需要可复现的 GPU 仿真或跨进程图序列化，v1.15 是合适的起点。但需注意确定性模式和纹理 API 仍标记为实验性，API 可能变化。

- **迁移成本集中在 v1.10–v1.13 的断代变更**：如果团队仍在使用 `warp.sim`，必须迁移到 Newton。如果代码依赖内部 API（`warp._src`、`warp.context` 等），需要在 v1.13 之前完成清理。Python 3.9 用户需要升级到 3.10+。CUDA 11 用户需要升级到 CUDA 12+。建议在升级前运行完整的回归测试套件。

- **目标用户画像**：Warp 最适合需要可微 GPU 计算的研究团队和仿真管线开发者，尤其是机器人学习（通过 Newton 或 JAX 集成）、物理仿真验证、以及需要跨平台（CPU/GPU）部署的场景。对于只需要传统物理引擎的用户，Newton 是更合适的选择。

- **生态和路线图观察点**：JAX 集成是 Warp 最明确的增长方向，v1.14 的稳定 API 表明 NVIDIA 正在将 Warp 定位为 JAX 生态中的可微计算后端。图捕获序列化（`.wrp` 格式）的成熟度将决定 Warp 能否成为跨语言仿真管线的标准中间表示。预计未来版本会继续扩展可捕获操作集、减少性能开销、并可能支持更多后端（如 AMD GPU 或 Apple Metal）。
