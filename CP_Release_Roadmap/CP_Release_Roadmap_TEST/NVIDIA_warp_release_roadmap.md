# NVIDIA/warp Release Roadmap

- 仓库: `NVIDIA/warp`
- 统计窗口: 最近一年
- 最新版本: v1.17.0 (2026-08-31 15:13:49 CST)
- 纳入统计的最早版本: v1.9.1 (2025-10-01 15:37:06 CST)
- 版本概况: 最近一年共 13 个版本，其中正式版 13 个、预发布版 0 个
- 详细证据索引: `NVIDIA_warp_release_roadmap_reference.md`

## 核心判断

- **Warp 正在从纯 GPU 仿真库演变为可移植的跨平台计算图运行时。** 过去一年中，v1.13 和 v1.14 引入了实验性的图捕获序列化（`.wrp` 格式），支持 CPU 和 GPU 回放，并允许从独立的 C++ 加载。v1.16 进一步扩展了 CPU 图与已保存图的回放操作范围，v1.17 则通过实验性的原生构建钩子让外部 C++/CUDA 集成可以直接向 Warp 内核暴露头文件定义的类型与函数。这意味着仿真管线可以跨进程、跨语言复用，不再局限于 Python 环境。

- **JAX 集成从实验性走向稳定，并扩展到 CPU 执行路径。** v1.10 引入了实验性的 JAX 自动微分支持，v1.12 增加了 `jax.vmap` 兼容性，v1.14 则提供了稳定的 JAX 集成 API。v1.16 新增了 JAX FFI 包装器的 CPU 支持，使同一份 `jax_kernel` 包装在 CPU 与 CUDA 上均可运行。对于已经使用 JAX 的团队，迁移成本较低。

- **物理仿真能力持续增强，但旧模块被剥离。** v1.10 正式移除了 `warp.sim` 模块，由独立的 Newton 物理引擎替代。同时，v1.14 新增了多环境 FEM 支持、可复用和批处理的线性求解器，v1.16 新增了固定容量 NanoVDB 体积的原地重建（含 CUDA 图捕获期间），v1.17 扩展了球体/胶囊体空间查询与 CG/CR 求解器周期性重启。这表明 NVIDIA 正在将核心仿真能力保留在 Warp 中，同时将更复杂的物理引擎外包给专门的生态项目。

- **平台兼容性收紧，Python 3.9 和 CUDA 11 被淘汰，同时新增 Windows ARM64 原生 CPU 构建路径。** v1.12 弃用了 Python 3.9，v1.13 正式移除支持，最低要求提升至 Python 3.10。CUDA 11 支持在 v1.8.1 后终止，v1.9 起要求 CUDA 12.x 或更新版本。同时，Intel 版 macOS（x86_64）在 v1.10 中被移除。v1.17 新增了从源码构建时对 Windows ARM64 的原生 CPU 支持，部分抵消了平台收紧带来的覆盖缺口。

## 产品演进主线

- **从 Python 专属到跨平台可移植计算图。** 过去一年，Warp 的核心演进方向是让仿真图（captured graphs）脱离 Python 环境运行。v1.13 引入了实验性的 `.wrp` 序列化格式和 CPU 回放，v1.14 进一步扩展了可捕获的操作范围（包括反向传播、tiled 内核、嵌套数组参数），v1.16 继续扩大 CPU 图与已保存图的回放操作覆盖。v1.17 引入实验性的原生构建钩子，允许附加包把自带的 C++/CUDA 头文件与函数暴露给 Warp 内核，并返回供外部构建或运行时系统使用的产物路径。对于需要将仿真集成到游戏引擎、机器人中间件或嵌入式系统的团队，这是关键能力。

- **JAX 生态深度整合，并覆盖 CPU 与 CUDA 双路径。** Warp 持续强化与 JAX 的互操作性。v1.10 支持通过 `jax.grad()` 对 Warp 内核求导，v1.12 增加了 `jax.vmap` 支持，v1.14 提供了稳定的 API。v1.16 新增 JAX FFI 包装器的 CPU 支持，同一份 `jax_kernel` 包装无需 Warp 设备参数即可在 CPU 与 CUDA 上运行。这表明 NVIDIA 将 JAX 视为可微分仿真的关键生态伙伴，而非竞争对手。

- **物理仿真能力模块化与专业化。** v1.10 移除了 `warp.sim` 模块，由独立的 Newton 物理引擎接管。与此同时，Warp 自身保留了并增强了核心仿真原语：v1.14 新增了多环境 FEM（用于批处理仿真）、可复用和批处理的线性求解器、便携式 tile FFT 和求解器回退；v1.16 新增固定容量 NanoVDB 体积原地重建与分组 HashGrid 查询；v1.17 新增球体/胶囊体 BVH 查询、网格三角形精确球体查询、网格内部 BVH 直接访问，以及 CG/CR 求解器周期性重启。这种“核心原语保留，复杂引擎外包”的策略，让 Warp 保持轻量级，同时通过生态项目覆盖更复杂的物理需求。

- **开发者体验与 API 清理持续推进。** v1.11 启动了大规模的 API 清理，将内部实现移至 `warp._src` 子包，并添加了弃用警告。v1.12 引入了下标风格的类型提示（如 `wp.array[dtype]`），改善了 IDE 集成。v1.13 移除了私有 API 转发 shim。v1.17 移除了 Python 与 Warp 数值标量到复合类型的隐式转换，并新增 CUDA 内核寄存器分配与共享内存溢出的调优与检查能力。这些变化虽然增加了短期迁移成本，但长期来看使 API 边界更清晰，降低了误用内部 API 的风险。

## 版本演进解读

### v1.17.0（2026-08-31）

- **几何查询与求解器能力扩展。** 新增 `wp.bvh_query_sphere()` 与 `wp.bvh_query_capsule()`，可直接用球体或胶囊体查询 BVH，无需先转换为 AABB；新增针对网格三角形的精确球体查询，并通过 `wp.mesh_get_bvh()` 暴露网格内部 BVH 给通用查询 API。tile 现在支持矩阵行索引（含读取、写入、负索引与伴随），CG 和 CR 求解器支持周期性重启且重启路径可用于 CUDA 图捕获。对于碰撞检测、射线查询和批处理线性求解场景，这些是直接的能力增强。
- **CUDA 内核资源调优与原生集成钩子。** 内核可通过 `cuda_max_registers` 控制寄存器分配与共享内存溢出，`wp.get_cuda_kernel_properties()` 可在不启动内核的情况下报告每线程寄存器数与本地内存使用。同时新增实验性的原生构建钩子，允许附加包把自带的 C++/CUDA 头文件与函数暴露给 Warp 内核，并返回供外部构建或运行时系统使用的产物路径。此外，从源码构建时新增 Windows ARM64 原生 CPU 支持。
- **迁移注意：** Python 与 Warp 数值标量到复合类型的隐式转换已被移除，需要按官方迁移指引调整代码。原生构建钩子为实验性功能，API 可能在没有正式弃用周期的情况下变化，官方尚未将其验证为完整的生产工作流。CUDA 内核资源计数依赖 GPU、工具链、编译选项与 block size，建议先用于排查占用率与溢出，再对内核做性能分析后调整配置。

### llvm-sdk-22.1.8-warp.1（2026-08-07）

- **这是预构建的 LLVM/Clang SDK，不是 Warp 版本发布。** 该 SDK 供 Warp 的 CPU-JIT 编译器（`warp-clang`）链接使用，基于 LLVM 22.1.8 源码构建，裁剪为仅含 clang 与静态库、无外部依赖，面向 host 后端与 NVPTX，并以体积优化为目标。
- **对多数用户无影响，对源码构建者是可选捷径。** 从 PyPI 安装 Warp 的用户可以忽略该页面；从源码构建的用户可以自行用 `build_lib.py --build-llvm` 编译 LLVM（约需一小时），这些归档只是省去该步骤的快捷方式。解压后可直接作为 `build_lib.py --llvm-path` 或 `WARP_LLVM_PATH` 使用。
- **平台与兼容性注意：** Linux 归档在 manylinux 容器内构建，glibc 下限为 x86_64 的 2.28 与 aarch64 的 2.34；windows-x86_64 使用 v142 工具集以保持可从 VS2019 链接，windows-arm64 使用 v143 且仍为实验性。下载可用 `sha256sum -c SHA256SUMS --ignore-missing` 校验。

### v1.16.0（2026-08-03）

- **NanoVDB 体积原地重建与分组 HashGrid 查询。** 新增固定容量 NanoVDB 体积的原地重建，包括在 CUDA 图捕获期间进行，使流体仿真可以在不分配新体积的情况下更新稀疏网格拓扑，并复用同一体积与依赖的 FEM 拓扑缓冲区跨图回放。同时新增面向多环境工作负载的分组 HashGrid 查询。对于 APIC 流体等活跃网格逐步变化的仿真，这消除了此前需要主机同步且无法在图内回放的分配开销。
- **tile 切片、JAX CPU 支持与图回放扩展。** 新增 NumPy 风格的 tile 切片；JAX FFI 包装器新增 CPU 支持，同一份 `jax_kernel` 包装在 CPU 与 CUDA 上均可运行；CPU 图与已保存的 `.wrp` 图支持回放更多操作；新增 CUDA profiler 范围控制。这些改进同时覆盖了可微分仿真工作流与跨平台部署工作流。
- **迁移注意：** 使用原地重建需在分配时显式启用（如 `rebuildable=True`）并配合容量估计，现有按步重新分配体积的代码需要改造才能获得图回放收益。JAX 包装器的标量输入仍要求为常量或静态值，被 trace 的标量参数会报错，需通过 `static_argnames` 处理。

### v1.15.0（2026-07-08）

- **确定性原子执行。** 新增 `wp.DeterministicMode.RUN_TO_RUN` 和 `GPU_TO_GPU` 模式，为支持的原子操作模式（如累加、槽位分配）提供位精确的可重复结果。对于仿真验证、回归测试和需要跨 GPU 架构保持结果一致的工作负载，这是关键能力。注意：确定性模式会改变执行算法并使用临时存储，性能影响因原子操作模式和竞争程度而异，建议在启用前对受影响的内核进行基准测试。

- **图回放能力扩展。** CPU 图和已保存的 CUDA 图现在支持更广泛的回放场景。结合 v1.14 对反向传播和 tiled 内核的捕获支持，v1.15 进一步缩小了图捕获与原生执行之间的功能差距。对于依赖图序列化进行跨进程或跨语言部署的团队，这是重要的稳定性提升。

- **CUDA 托管内存分配与 mipmapped 纹理。** 新增 CUDA 托管内存分配支持，允许在统一内存系统中更灵活地管理 GPU 和 CPU 内存。同时新增 mipmapped 纹理支持，为渲染和体积采样场景提供更高效的纹理采样能力。对于处理大规模数据集或需要精细纹理 LOD 控制的应用，这些是实用增强。

- **迁移注意：** 确定性模式是 opt-in 功能，默认不启用。使用 `wp.set_module_options({"deterministic": wp.DeterministicMode.RUN_TO_RUN})` 启用。注意：确定性模式与自动微分结合使用时，Pattern 2 槽位分配（消费槽位值）不被支持，会拒绝启动。建议在启用前阅读官方文档中的性能影响说明。

### v1.14.0 (2026-06-01)

- **图捕获能力大幅扩展。** CPU 图捕获现在支持反向传播（`wp.Tape().backward()`）、`wp.launch_tiled()` 内核、任意大小的标量参数，以及包含数组的 `@wp.struct` 和 `wp.indexedarray` 参数。这使得更复杂的仿真管线可以被序列化和回放。
- **多环境 FEM 和批处理求解器。** 新增多环境 FEM 支持，用于批处理仿真。线性求解器现在可复用且支持批处理，tile FFT 和求解器具有便携式回退机制。对于需要大规模并行仿真的团队（如机器人训练），这是重要能力。
- **迁移注意：** APIC 格式版本升级到 10，v1.13 保存的 `.wrp` 文件需要重新捕获。C/C++ APIC 句柄声明需要改为显式指针（如 `APICState*`）。FEM 的部分位置参数签名有变化。

### v1.13.0 (2026-05-04)

- **实验性图捕获序列化与 CPU 回放。** 这是本年度最重要的架构变化。通过 `wp.capture_save()` 和 `wp.capture_load()`，仿真图可以保存为 `.wrp` 文件，并在 Python 或独立 C++ 中回放。CPU 回放是新增能力，使得仿真可以在无 GPU 的环境中运行。
- **cuBQL BVH 后端。** 为 `wp.Mesh` 添加了实验性的 cuBQL BVH 构建器，在密集静态网格的射线查询场景中，仿真时间可降低约 30%（从 1.41 秒降至 0.98 秒，RTX 4090 测试）。对于渲染和碰撞检测密集型应用，这是显著的性能提升。
- **可插拔 CUDA 分配器与 RMM 集成。** 新增 `wp.set_cuda_allocator()` 接口，支持 RAPIDS Memory Manager (RMM) 集成，使 Warp 可以与 PyTorch、CuPy 共享内存池，减少 GPU 内存碎片。
- **迁移注意：** Python 3.9 支持被移除，最低要求 Python 3.10。私有 API 转发 shim 被移除，使用 `warp._src` 内部路径的代码将报错。

### v1.12.1 (2026-04-06)

- **Tile 正确性修复。** 修复了多个 tile 内核问题，包括 `block_dim` 跨设备错误、`tile_matmul()` 和 `tile_fft()` 忽略 `enable_backward`、共享内存 tile 编译失败等。对于依赖 tile 编程的用户，这是重要的稳定性更新。
- **Omniverse Kit 扩展移除。** 从仓库中移除了 Omniverse Kit 扩展。如果团队依赖这些扩展，需要规划替代方案。
- **迁移注意：** 宣布 Python 3.9 支持将在 v1.13 移除。`wp.isfinite()`、`wp.isnan()`、`wp.isinf()` 将不再接受整数类型。

### v1.12.0 (2026-03-07)

- **硬件加速纹理采样。** 新增 `wp.Texture1D`、`wp.Texture2D`、`wp.Texture3D`，利用 CUDA 纹理内存进行硬件加速插值。适用于渲染、体积采样、符号距离场查询和仿真查找表。CPU 上有软件回退，保证跨设备兼容。
- **Tile 编程增强。** 新增逐元素算术运算符（`tile_mul`、`tile_div`）和可微分的 FFT。tile FFT 现在支持 N >= 2 维度的张量，沿最后一维计算 FFT。
- **JAX 互操作性扩展。** 支持 `jax.vmap`，使 Warp 内核可以参与 JAX 的向量化映射。
- **迁移注意：** Python 3.9 被弃用。隐式标量到复合类型的转换被弃用。矩阵从向量构造的 `wp.matrix()` 被移除，需使用 `wp.matrix_from_rows()` 或 `wp.matrix_from_cols()`。

### v1.11.1 (2026-02-04)

- **CUDA 图内存优化。** 修复了 CUDA 图中多个临时分配导致内存过度累积的问题（例如三个 1GB 分配消耗 3GB 而非复用 1GB）。对于使用 CUDA 图进行高性能仿真的用户，这是重要的内存效率修复。
- **开发者体验改进。** 修复了 `@wp.func` 在 Pyright/Pylance 中显示泛型类型的问题，以及 IDE 自动补全存根的多项错误。IDE 集成质量得到提升。
- **迁移注意：** 矩阵从向量构造的 `wp.matrix()` 在 Python 作用域被弃用。

### v1.11.0 (2026-01-02)

- **分组感知空间查询。** 新增 `wp.Bvh` 和 `wp.Mesh` 的分组感知构建和查询，允许在单个加速结构中包含多个独立环境（世界），并独立查询每个世界。对于多世界仿真（如机器人训练中的并行场景），这是关键能力。
- **JIT 编译管理新选项。** 新增 `wp.force_load()` 用于显式控制模块编译，以及预编译头支持以加速 CUDA 编译。对于大型项目，编译时间管理变得更加可控。
- **API 清理启动。** 内部 API 访问开始发出弃用警告，计划在 v1.13 移除。公共 API 被明确记录在重构的文档中。团队应开始检查代码中是否有对 `wp.context` 等内部符号的依赖。

### v1.10.1 (2025-12-01)

- **FEM 和自定义梯度修复。** 修复了 `wp.fem.TemporaryStore` 在 tape 捕获期间的无效读取，以及自定义梯度函数在嵌套调用时的编译顺序问题。对于使用 FEM 和自定义梯度的用户，这是重要的稳定性更新。
- **迁移注意：** `jax_callable()` 的 `graph_compatible` 参数被弃用，需改用 `graph_mode` 枚举。Python 3.8 支持即将移除。

### v1.10.0 (2025-11-02)

- **JAX 自动微分（实验性）。** Warp 内核现在可以参与 JAX 的自动微分流程，通过 `jax.grad()` 计算梯度。支持单输出和多输出内核，标量输入自动视为静态。这是 Warp 与 JAX 生态融合的关键一步。
- **`warp.sim` 模块移除。** 该模块被正式移除，由独立的 Newton 物理引擎替代。如果团队仍在使用 `warp.sim`，需要迁移到 Newton。
- **性能优化。** Python 作用域的内置函数调用速度提升高达 70 倍。BVH 支持原地重建和可配置叶子大小。稀疏矩阵和 FEM 操作现在可被 CUDA 图捕获。
- **迁移注意：** 列表、元组等非 Warp 数组参数传递给内置函数不再支持，需使用显式类型构造器。`wp.Bvh` 的默认 `leaf_size` 从 4 改为 1。Intel 版 macOS（x86_64）支持被移除。

### v1.9.1 (2025-10-01)

- **GPU 架构兼容性修复。** 恢复了 v1.9.0 预构建 wheels 中意外丢失的 Maxwell、Pascal、Volta 架构支持。对于使用较旧 GPU 的团队，这是关键修复。
- **Tile 内存管理修复。** 修复了共享 tile 的双重释放和内存泄漏问题。`wp.copy()` 和 `wp.where()` 现在支持 tile 并计算正确的梯度。
- **迁移注意：** 宣布 `warp.sim` 将在 v1.10 移除。ARM64 CPU 内核存在段错误问题，计划在 v1.10 修复。

### v1.9.0 (2025-09-05)

- **可微分 Marching Cubes。** 完全用 Warp 重写的 Marching Cubes 实现，支持 CPU 和 GPU，且可微分。替换了之前的原生 CUDA C++ 实现，修复了长期存在的 off-by-one 错误。对于体积网格提取和可微分几何处理，这是重要能力。
- **CUDA 13 支持。** 兼容 CUDA Toolkit 13.0，但 PyPI wheels 仍使用 CUDA 12.8 构建以提供过渡期。
- **AOT 编译增强。** 新增 `wp.compile_aot_module()` 和 `wp.load_aot_module()`，支持 `strip_hash=True` 以分发预编译模块而不泄露源代码。
- **迁移注意：** CUDA 11 支持终止。`warp.sim` 被弃用。

### v1.8.1 (2025-08-02)

- **MuJoCo MJX 支持。** 为 `jax_experimental` 模块添加了新的 `graph_mode` 参数（`GraphMode.WARP`），支持捕获包含条件节点的图。这是为了支持 MuJoCo MJX 物理引擎的采用。
- **CUDA 11 最终版本。** 这是最后一个支持 CUDA 11.x 的版本。团队需要规划迁移到 CUDA 12.x。
- **性能修复。** 修复了使用 matmul、Cholesky 和 FFT 求解器的内核编译时间回归问题（通过升级 libmathdx 0.2.2）。

## 采用与规划提示

- **立即评估图捕获序列化（v1.13+）的采用价值。** 如果您的团队需要将仿真部署到生产环境、嵌入 C++ 应用，或实现跨进程仿真复用，v1.14 的图捕获能力已经覆盖了足够多的场景（包括反向传播和 tiled 内核），v1.16 进一步扩大了 CPU 图与已保存图的回放操作范围。建议在 v1.16 或更新版本上开始原型验证，因为 APIC 格式版本已更新，v1.13 的文件需要重新捕获。注意该功能仍为实验性，API 可能变化。

- **规划 Python 3.9 和 CUDA 11 的升级路径。** Python 3.9 支持已在 v1.13 移除，CUDA 11 支持在 v1.9 终止。如果您的环境仍在使用这些版本，升级到 Python 3.10+ 和 CUDA 12.x 是使用最新 Warp 版本的前提条件。同时，Intel 版 macOS（x86_64）用户需要迁移到 Apple Silicon 或考虑替代方案；Windows ARM64 用户可从 v1.17 起通过源码构建获得原生 CPU 支持。

- **关注 JAX 集成与原生扩展两条路线。** Warp 与 JAX 的集成正在快速成熟，v1.16 已让同一份 `jax_kernel` 包装在 CPU 与 CUDA 上通用。如果您的团队使用 JAX 进行可微分编程或机器人学习，v1.14 的稳定 JAX API 值得采用。同时，v1.17 的实验性原生构建钩子为需要把自有 C++/CUDA 代码接入 Warp 内核的团队提供了路径，但官方尚未验证其为完整生产工作流，建议仅用于评估。

- **为 API 清理与标量转换移除预留迁移预算。** v1.11 启动的 API 清理（内部符号移至 `warp._src`、弃用警告）已在 v1.13 最终生效；v1.17 进一步移除了 Python 与 Warp 数值标量到复合类型的隐式转换。如果您的代码库直接引用了 `warp.context`、`warp.torch` 等内部路径，使用了 `wp.matrix()` 从向量构造矩阵的旧语法，或依赖标量到复合类型的隐式转换，建议在升级到 v1.17 之前完成迁移。使用 `wp.config.verbose_warnings = True` 可以定位所有弃用用法。
