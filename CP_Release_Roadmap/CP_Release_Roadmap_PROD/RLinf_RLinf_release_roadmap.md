# RLinf/RLinf Release Roadmap

- 仓库: `RLinf/RLinf`
- 统计窗口: 最近一年
- 最新版本: v0.4 (2026-10-20 18:46:17 CST)
- 纳入统计的最早版本: v0.1 (2025-12-17 20:01:25 CST)
- 版本概况: 最近一年共 4 个版本，其中正式版 4 个、预发布版 0 个
- 详细证据索引: `RLinf_RLinf_release_roadmap_reference.md`

## 核心判断

- **v0.4 将 RLinf 从“端到端真实世界训练流水线”推进到“真实世界规模化部署”阶段。** v0.3 打通了数据采集 → SFT → RL → 部署的完整链路；v0.4 围绕模块化真机系统、高效真机算法、全模态模型与异构算力底座三大支柱重构技术栈，产品定位从“训练框架”升级为“具身强化学习的规模化落地基础设施”。

- **模块化真机系统（`rlinf.robotics`）是 v0.4 最具结构性意义的变化。** 机械臂、灵巧手、相机、移动底盘与遥操作设备被抽象为可组合部件，硬件驱动与任务逻辑完全解耦，更换机器人本体、配置或跨节点部署无需改动任务或策略代码。这直接降低了真机场景的集成与迁移成本。

- **v0.4 补齐了真机训练的关键算法短板。** 表示解耦在线 RL（RLT）、无标签自监督离线 RL（STEAM）、30 步内达到 96%+ 成功率的在线策略蒸馏（OPD），以及将推理等待压缩至约 2 ms 的异步实时控制（RTC），分别针对真机样本昂贵、标注成本高、推理卡顿三类核心痛点。

- **生态与算力覆盖同步扩张。** 新增昆仑芯、壁仞、沐曦、Intel XPU 等加速后端，华为昇腾与摩尔线程实现最高 2.78× 吞吐且收敛对齐 A100；RLinf 加入 PyTorch 生态，并作为 NVIDIA Isaac Lab v3.0 的 RL 训练引擎。这使 RLinf 的适用范围从单一 GPU 环境扩展到国产与异构算力场景。

## 产品演进主线

- **从“打通链路”到“规模化部署”的阶段性跃迁。** v0.1 建立系统抽象与仿真性能优势，v0.2 引入真实机器人与世界模型仿真器，v0.3 完成端到端真实世界训练闭环，v0.4 则以模块化真机系统与高效真机算法支撑真实世界规模的具身 RL 部署。主线从能力覆盖转向工程可落地性。

- **真机硬件支持从“逐机型适配”转向“可组合部件体系”。** v0.3 以 Franka 双臂、灵巧手、GELLO 等具体工作流扩展硬件覆盖；v0.4 将这些硬件抽象为可组合部件，驱动与任务逻辑解耦，并支持跨节点部署与部件级替换。硬件扩展方式由新增机型文档变为体系化复用。

- **模型生态从 VLA 扩展到全模态与视觉生成。** v0.3 新增 DreamZero、GR00T-N1.6/N1.7、ABot-M0、StarVLA、LingBot-VLA 等具身模型；v0.4 引入 PyTorch 原生 OpenPI（π₀ / π₀.₅，逐算子对齐官方 JAX 数值）、Cosmos3、FastWAM、π₀-FAST、Evo-1、MolmoAct2，并首次将 RL 扩展到 SD3 / Wan2.2 视觉生成。

- **算力与生态从 GPU 单一路径扩展到异构多后端。** v0.1 已支持 GPU、NPU、CPU 异构资源管理；v0.4 将加速后端扩展到八个，并进入 PyTorch 生态与 NVIDIA Isaac Lab v3.0。RLinf 的部署边界从研究集群延伸到国产算力与主流生态集成场景。

## 版本演进解读

### v0.4（2026-10-20）

- **模块化真机系统落地为 `rlinf.robotics`。** 机械臂、灵巧手、相机、移动底盘与遥操作设备成为可组合部件，硬件驱动与任务逻辑解耦，更换机器人本体、配置或跨节点部署无需改动任务或策略代码；文档给出统一的构建、连接、观测与动作下发生命周期，并支持部件级注册扩展（如自定义末端执行器）。对产品而言，这降低了新硬件接入与多机部署的集成成本。

- **真机后训练算法与全模态模型同步补齐。** 新增 RLT（表示解耦在线 RL）、STEAM（无标签自监督离线 RL）、OPD（30 步内 96%+ 成功率）与 RTC（推理等待约 2 ms）；模型侧引入 PyTorch 原生 OpenPI（π₀ / π₀.₅，逐算子对齐官方 JAX 数值）、Cosmos3、FastWAM、π₀-FAST、Evo-1、MolmoAct2，并首次将 RL 扩展到 SD3 / Wan2.2 视觉生成。这使真机样本效率、标注成本与推理实时性三类瓶颈同时得到针对性回应。

- **兼容性与迁移说明。** 提供的来源未明确描述破坏性变更。真机工作流文档被重组为按硬件划分的索引（单臂 Franka、双臂 Franka、GimArm、XSquare Turtle2、Dexmal DOS-W1、AgileX Piper、SO101），双臂 Franka 新增 PICO 遥操作 HG-DAgger 与 OpenPI PyTorch 两条工作流；已有 Franka 用户需按新索引重新定位对应配置与入口。异构算力用户需确认所选后端（昆仑芯、壁仞、沐曦、Intel XPU、昇腾、摩尔线程）的可用性。

### v0.3（2026-07-15）

- **端到端真实世界训练流水线正式完成。** 新增了从数据采集（collect_real_data.py）、SFT（train_vla_sft.py）、RL 到部署的完整工作流文档。Franka 机械臂的支持从单臂扩展到双臂配置（dual_franka），并新增了灵巧手（dexhand）、GELLO 关节级遥操作、ZED 相机和 Robotiq 夹爪等多样化硬件工作流。这意味着用户可以在同一框架内完成从数据收集到策略部署的全流程。

- **模型生态大幅扩展，新增 6 个具身模型。** 包括 DreamZero（从 WAN2.1/2.2 视频生成世界模型微调的 VLA 策略，通过 FSDP2/CUDA Graph 实现近 4 倍吞吐量提升）、GR00T-N1.6/N1.7、ABot-M0、StarVLA（LIBERO 上的 GRPO 微调）、LingBot-VLA（RoboTwin 环境 SFT/RL）以及 Dexbotic DM0（LIBERO 上的 PPO 在线 RL 微调）。同时新增了 5 个仿真器，拓宽了仿真 RL 的场景覆盖。

- **SFT 被明确定位为 RL 冷启动的标准前置步骤。** 新增了专门的 SFT 索引页面，将监督微调作为具身强化学习的标准前置阶段。DreamZero 模型展示了从视频生成世界模型到 VLA 策略的 SFT 流程，支持 WAN2.1 和 WAN2.2 主干，并提供了 LIBERO、DROID、Franka PnP 等多种数据集的 SFT 配方。

- **兼容性与迁移说明。** 提供的来源未明确描述破坏性变更。新增的 Docker 镜像标签为 `agentic-rlinf0.3-maniskill_libero`，建议用户参考官方文档中的安装指南进行环境迁移。文档结构进行了重新组织，新增了真实机器人索引和 SFT 索引页面。

### v0.2（2026-03-26）

- **真实世界强化学习成为核心能力。** 新增对 XSquare Turtle2 双臂机器人和 Franka 机械臂的真实机器人训练支持，支持 SAC、Cross-Q、RLPD 等算法，并提供完整的 Docker 镜像和安装指南。这意味着用户可以直接在真实机器人上运行强化学习训练，而不仅限于仿真环境。

- **世界模型作为仿真器引入。** 支持 OpenSora、Wan、WoVR 三种世界模型作为强化学习训练的仿真环境，能够生成“想象”的轨迹来优化 VLA 策略。这为 Sim-to-Real 和 Real2Sim2Real 训练提供了新的技术路径，降低了真实机器人训练的成本和风险。

- **原生多智能体训练支持。** 引入了可扩展的多智能体强化学习算法和统一数据接口，能够复现 WideSeek-R1 等复杂多智能体解决方案。同时，PPO 扩展到了推理任务场景（Reasoning PPO），并支持了 rStar2 和 Search-R1 等智能体强化学习方案。

- **训练基础设施全面升级。** 新增原生异步训练（Async PPO）支持，引入 CUDA Graph、torch.compile、环境卸载、FSDP 路径优化等性能优化。重构了数据收集和回放缓冲区架构，增强了缓冲区预加载、更新和检查点处理能力。这些改进显著提升了高吞吐训练效率。

- **模型与算法生态大幅扩展。** 新增对 Dexbotic 模型、openpi 模型族、RoboTwin 2.0 的支持，引入 SAC-Flow、DSRL、VLM SFT 等新算法。新增 CALVIN、RoboCasa 等基准测试支持，并验证了 Robo2VLM 数据集的 SFT 效果（约 95% 的复现准确率）。同时，Megatron 后端新增 FUSCO 通信库支持，提升了 MoE 训练和推理的 All-to-All 通信性能。

- **兼容性与迁移说明。** 提供的来源未明确描述破坏性变更。FSDP 精度处理被重构为仅支持 fp16 和 bf16，但保留了向后兼容性。文档被重新组织，示例被分类为具身、智能体和系统级优化三类。

### v0.1（2025-12-17）

- **首个公开版本，奠定了框架的架构基础。** 引入了 Worker/Scheduler/Channel 三层系统抽象，支持 GPU、NPU、CPU 异构资源管理，以及自动 GPU 资源调度和动态组件扩缩容。Channel 提供了自适应高性能通信，自动选择最优通信后端（零拷贝 cudaIPC、NCCL、Gloo 等）。

- **在具身强化学习场景验证了显著性能优势。** 支持 ManiSkill、LIBERO、MetaWorld、CALVIN、IsaacLab、BEHAVIOR-1K 等主流仿真器，以及 OpenVLA、π₀、GR00T 等 VLA 模型。在多个基准测试上达到最高 99% 的成功率，训练吞吐量比现有框架最高提升 143.4%（2.434 倍），并支持灵活分配、解耦和混合执行模式。

- **在推理和智能体场景展示了强大能力。** 使用 1.5B 和 7B 模型在 AIME 24、AIME 25、GPQA-Diamond 等基准测试上达到最先进结果。通过流水线并行（20%+ 加速）和自动调度（30%+ 加速）显著提升效率。引入了首个开源 1.5B 在线强化学习智能体，代码补全准确率提升 50%+，超越 32B 规模模型。

- **支持多种算法和训练后端。** 支持 GRPO、PPO、DAPO、REINFORCE++ 等算法，以及 Megatron、FSDP 训练后端和 SGLang、vLLM、HuggingFace 推理后端。提供了统一的算法、环境和模型接口。

## 采用与规划提示

- **v0.4 适合计划将具身 RL 从实验环境推进到真实世界规模化部署的团队。** 模块化真机系统使硬件替换与跨节点部署不再牵动任务代码，建议新项目直接基于 `rlinf.robotics` 的部件体系设计硬件接入方案，而非沿用逐机型适配方式。

- **真机算法选型应围绕样本成本与实时性约束展开。** 样本昂贵场景可优先评估 RLT 与 STEAM，标注受限场景关注 STEAM 的无标签自监督路径，对推理延迟敏感的高频控制任务关注 RTC 与 OPD。上述指标来自发布说明，实际效果需在自有硬件与任务上验证。

- **已有 Franka 用户需按新文档索引完成迁移核对。** 真机工作流已重组为按硬件划分的索引，双臂 Franka 新增 PICO HG-DAgger 与 OpenPI PyTorch 工作流；建议先确认所用配置与入口在新索引中的对应位置，再评估是否需要切换到 PyTorch 原生 OpenPI。

- **异构算力与生态集成是 v0.4 的新增评估维度。** 八个加速后端与 PyTorch 生态、Isaac Lab v3.0 集成扩大了部署选择，但不同后端的可用性与收敛表现需按实际环境验证；国产算力用户应优先确认目标后端是否在支持列表内。
