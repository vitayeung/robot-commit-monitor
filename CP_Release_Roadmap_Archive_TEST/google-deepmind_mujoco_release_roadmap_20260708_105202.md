# Release Roadmap

- 仓库: `google-deepmind/mujoco`
- 统计窗口: 最近一年
- 最新版本: 3.10.0 (2026-06-23 01:04:32 CST)
- 纳入统计的最早版本: 3.3.4 (2025-07-10 04:14:25 CST)
- 版本概况: 最近一年共 12 个版本，其中正式版 12 个、预发布版 0 个
- 详细证据索引: `google-deepmind_mujoco_release_roadmap_reference.md`

## 核心判断

- **MuJoCo 在过去一年中从物理仿真引擎加速演变为一个面向机器人学和可变形体仿真的全栈平台。** 新增了系统辨识工具箱、DC 电机执行器、柔性体（flex）的隐式积分和二次型自由度、以及多种新型传感器（接触、触觉、内部位置）。这些能力使产品从单纯的仿真器扩展到模型辨识、控制开发和传感器仿真工作流。

- **MJX（基于 JAX 的加速后端）和 Warp 后端的引入是生态扩展的关键决策。** 3.3.5 版本正式将 Warp 作为 MJX 的 GPU 后端实现，3.6.0 版本增加了 MJX-Warp 批量渲染支持。这意味着用户现在可以在 GPU 上大规模并行运行仿真，同时保持与 MuJoCo 原生模型格式的兼容性，显著降低了从原型到规模化仿真的迁移成本。

- **API 稳定性与演进之间存在明确权衡，团队正在为未来的破坏性变更做准备。** 多个版本引入了弃用标记（如 `mju_user_error`/`mju_user_warning` 回调、`mjtByte` 布尔类型、旧式 `mj_fullM` 签名），同时新增了 `mjtBool` 类型、`mjassert.h` ABI 稳定性头文件、以及 `mjs_setName` 等更安全的 API。产品经理应预期在 3.11 或 4.0 版本中会有一次集中的 API 清理。

- **可变形体（flex）和接触传感器是过去一年中投入最大的两个产品方向。** 从 3.3.5 的接触/触觉传感器，到 3.4.0 的 flex 二次型自由度，再到 3.5.0 的 flex 顶点约束和隐式积分，再到 3.8.0 的多单元 flex 支持，柔性体仿真能力在每个版本中都有实质性增强。这表明 DeepMind 正将 MuJoCo 定位为机器人操作和布料仿真领域的核心工具。

## 产品演进主线

- **传感器生态从基础测量向高级感知能力扩展。** 过去一年新增了接触传感器（报告用户定义的接触信息）、触觉传感器（测量穿透深度和滑动速度）、内部位置传感器（检测物体是否在站点体积内）、以及 rangefinder 传感器对相机的支持。这些传感器直接服务于机器人感知和操作任务，使 MuJoCo 能够更真实地模拟触觉和接近觉传感器。

- **可变形体仿真能力从实验性功能升级为一级产品特性。** 3.3.5 移除了 SdfLib 插件，将 SDF 支持原生集成到 mjModel 中。3.4.0 增加了 flex 的二次型自由度（quadratic dof），支持弯曲变形。3.5.0 增加了 flex 顶点约束（flexvert equality），使布料仿真可以使用更粗的网格。3.7.0 增加了 flex 的隐式积分支持。3.8.0 增加了多单元 flex 支持。这些变化使 MuJoCo 在软体机器人、布料仿真和生物力学领域的适用性大幅提升。

- **求解器质量和数值稳定性持续改进，特别是在 float32 精度下。** 3.8.0 默认启用了新的碰撞管线。3.9.0 增加了 `diagexact` 标志，可精确计算约束空间惯性矩阵的对角线，改善各向异性惯性和复杂运动学耦合模型的求解质量。3.10.0 将 CG 求解器的共轭方向更新从 Polak-Ribiere-Plus 改为 Hager-Zhang 公式，显著提升了 float32 下的收敛速度和性能。

- **Python 生态和开发者体验持续优化。** 新增了 Python 虚拟文件系统绑定（3.8.1）、Python spec 元素的编译器设置查询（3.6.0）、系统辨识工具箱（3.5.0）、以及批量渲染支持（3.6.0）。Python 3.14 支持在 3.8.0 中已添加。这些改进降低了 Python 用户的使用门槛，使 MuJoCo 更易于集成到现代机器学习工作流中。

## 版本演进解读

### 3.10.0 (2026-06-23)

- 新增了统一的日志记录 API，弃用了旧的 `mju_user_error` 和 `mju_user_warning` 回调函数。新增 `mjs_numWarnings` 和 `mjs_getWarning` 用于检索编译和附着过程中累积的所有警告。这改善了错误处理和调试体验。
- CG 求解器改用 Hager-Zhang 共轭方向更新公式，替代了 Polak-Ribiere-Plus 公式。这显著提升了 float32 下的收敛速度和性能，对 GPU 仿真场景尤为重要。
- 新增 `mju_threadpool` 函数用于创建工作线程池，替代了旧的引擎线程 API。新增 `compiler/conflict` 属性用于控制全局属性冲突时的合并策略（当前默认策略为报错，未来将改为合并）。
- 新增 `mjs_makeFlex` C API 函数，等价于 `flexcomp` XML 元素。支持从 OBJ 线段加载 1D flex 组件。改进了 `maxhullvert` 属性生成的凸包质量。

### 3.9.0 (2026-05-27)

- 新增 `diagexact` 标志，可在当前配置下精确计算约束空间惯性矩阵的对角线，替代默认的编译时近似。这改善了各向异性惯性和复杂运动学耦合模型的求解器质量。
- 新增编译器计时诊断功能，通过 `mjtCTimer` 枚举和 `mjs_getTimer` C API 提供。编译后可获取按类别划分的耗时（总时间、资产、网格加载、凸包、法线、惯性、BVH、八叉树等）。
- 新增 `mjtBool` 类型替代 `mjtByte`，用于所有 `mjModel`、`mjData` 和公共 C API 函数签名中的布尔字段。大多数模型无需修改，但自定义代码中使用了 `mjtByte` 布尔字段的需要迁移。
- 触觉传感器现在报告原始深度而非估计压力。这是一个行为变化，可能影响依赖压力值的现有模型。

### 3.8.1 (2026-05-11)

- PGS 求解器新增岛支持，并以伪随机顺序迭代约束，提升了性能。这扩展了岛求解器的适用范围。
- 新增对三线性和二次型 flex 自由度的 `elastic2d` 支持。新增 `mjs_getOriginSpec` 函数，可返回元素在附着前原始定义的 spec。
- 新增 `mju_sym2dense` 函数，用于将下三角隐式对称 CSR 矩阵转换为稠密对称矩阵。这是为未来移除旧格式 `mj_fullM` 做准备。

### 3.8.0 (2026-04-25)

- 新增 Python 3.14 支持。新增三线性和二次型 flex 的多单元支持（multi-cell），但隐式积分器对 flex 自由度使用稠密求解器，多单元场景下可能较慢。
- 新增 `mj_maxContact` 函数，可获取 `mj_collide` 可能返回的最大接触数。新的碰撞管线现在默认启用，性能开销小且稳定性更好。
- 关节和肌腱的刚度/阻尼现在支持非线性多项式力曲线。新增 `mjNPOLY` 常量定义多项式阶数，未来 C API 将有一次破坏性变更。
- 新增 DC 电机执行器（dcmotor），支持可选的反射阻尼和惯性（通过 gear² 缩放）。这对机器人驱动建模非常重要。

### 3.7.0 (2026-04-14)

- 新增 DC 电机执行器，支持反射阻尼和惯性。新增关节和肌腱刚度/阻尼的非线性多项式力曲线。
- 新增独立自由体的中点积分。为 connect 和 weld 等式约束添加了向心/科里奥利加速度项（Ĵv），显著改善了高速运动下的约束精度。
- 移除了 `mjsFlex` 中的 `collision` 字段，因为 MuJoCo Warp 已原生支持 flex 碰撞。URDF 解析不再硬编码 `strippath` 为 true，现在尊重用户设置。
- `mjPLUGIN_LIB_INIT` 宏现在需要 name 参数以避免初始化函数名冲突。MSVC 构建改用 C 运行时初始化段来初始化插件。

### 3.6.0 (2026-03-10)

- 新增 `mjs_getCompiler` C API 函数和 Python spec 元素的只读 `compiler` 属性，可在编译后查询编译器设置。Flex 现在支持与 SDF 几何体的碰撞。
- 新增 MJX-Warp 批量渲染支持。新增 `mj_mountVFS` 和 `mj_unmountVFS` 函数，支持挂载自定义 VFS 提供者。
- 移除了顺序碰撞传感器共享计算的优化，可能导致轻微性能回退。可通过 `fromto` 属性恢复性能。
- `mjModel` 的分配大小改用 64 位整数以支持更大场景。`mj_stateSize` 等函数的 `signature` 参数类型已更改。

### 3.5.0 (2026-02-13)

- 新增系统辨识工具箱（Python），支持从轨迹数据辨识模型参数。新增执行器和传感器的任意延迟支持（通过历史缓冲区），传感器值可在任意时间点计算。
- 新增 flex 顶点等式约束（flexvert），支持使用更粗网格进行布料仿真。新增 flex 的隐式积分支持。
- Rangefinder 传感器现在可附着到相机，并遵循相机的分辨率属性。射线投射函数现在可选计算表面法线（破坏性变更）。
- 相机 MJCF 属性已重命名为 `camera/projection`，支持更多投影类型。新增 `mj_mountVFS`/`mj_unmountVFS` 函数。

### 3.4.0 (2025-12-06)

- 新增 flex 的二次型自由度选项（quadratic dof），支持弯曲变形。Windows 栈大小增加到 16MB 以支持深层嵌套 body 层次结构。
- 新增 `mj_fwdKinematics` 管线组件函数，整合所有运动学子组件。新增 `mj_copyState` 函数用于复制状态组件。
- 肌腱路径现在可从 Python 查询。OpenUSD 可选依赖更新到 1.10.0。MJX 的批量渲染器将迁移到 Warp 后端。

### 3.3.7 (2025-10-15)

- `mjSpec` C API 的 `meshdir` 和 `texturedir` 字段已移至 `compiler.meshdir` 和 `compiler.texturedir`。Python API 中旧字段仍可用但将在未来版本移除。
- 新增 `mju_getXMLDependencies` 函数，可计算 MJCF 文件的唯一资产依赖列表。最低 C++ 标准要求提升到 C++20。
- 修复了 `fitaabb` 对网格添加偏移量并应用错误帧变换的问题。

### 3.3.6 (2025-09-15)

- 接触传感器的 `subtree1`/`subtree2` 规范现在适用于任何 body。约束求解器的 `efc_force` 更新从 `mj_fwdConstraint` 末尾移至 `mj_step` 末尾，使 `mj_forward` 完全幂等。
- RK4 积分器的行为因上述变更而改变：之前的收敛更快但不规范，现在积分是规范且定义良好的。这是一个有效的 bug 修复，但可能影响依赖旧行为的模型。
- 禁用被动力的标志已移除，替换为 `mjDSBL_SPRING` 和 `mjDSBL_DAMPER`，分别禁用关节和肌腱的弹簧/阻尼力。新增 flex 被动接触的实验性选项。

### 3.3.5 (2025-08-09)

- 新增三种传感器：`insidesite`（检测对象是否在站点体积内）、`contact`（按用户定义报告接触信息）、`tactile`（测量穿透深度和滑动速度）。这些传感器直接服务于机器人操作和触觉仿真。
- 移除了 SdfLib 插件及其依赖，SDF 现在原生支持在 mjModel 中。新增内置网格创建功能（`mesh/builtin`）。
- 新增 `mj_makeM` 函数，结合了 CRB 算法和肌腱 armature 相关项。使用 `mj_crb` 计算惯性的代码应改用 `mj_makeM`。
- 新增 Warp 作为 MJX 的后端实现，可通过 `mjx.backend` 指定。Linux wheels 现在基于 manylinux_2_28（替代已 EOL 的 CentOS 7）。

### 3.3.4 (2025-07-08)

- 新增通过 `visual/global/cameraid` 设置查看器初始相机的支持。Python passive 查看器新增仅同步状态的选项，可提升性能。
- `mjSpec` C API 中，`mjs_setString` 设置元素名称的功能已被 `mjs_setName` 替代，后者可在设置时检查命名冲突。`name` 属性已从所有 `mjs` 元素中移除。
- 移除了 `shell` 插件，其功能已由 `flexcomp` 的 `elastic2d` 属性支持。移除了 `mjsPartialCopy` 结构体，其功能由 `mjv_copyModel` 和 `mjv_copyData` 提供。

## 采用与规划提示

- **当前（3.10.0）是采用新功能的最佳时机，但需注意 API 弃用信号。** 如果团队正在开发新的机器人仿真或控制项目，建议从 3.9.0 或 3.10.0 开始。但需注意 `mju_user_error`/`mju_user_warning` 回调、`mjtByte` 布尔类型、以及旧式 `mj_fullM` 签名已被弃用。新代码应直接使用新的日志 API、`mjtBool` 类型和 `mju_sym2dense` 函数。

- **MJX-Warp 后端为大规模并行仿真提供了清晰的路径，但迁移成本取决于现有代码。** 如果团队已经在使用 MJX（JAX 后端），迁移到 Warp 后端可以获得批量渲染和更高效的 GPU 利用。如果团队主要使用原生 MuJoCo C/C++ API，则无需立即迁移，但应关注 MJX 生态的发展，因为未来新功能（如 flex 碰撞）可能优先在 Warp 后端实现。

- **可变形体（flex）和传感器生态的快速扩展意味着产品定位正在从纯物理引擎向机器人仿真平台转变。** 对于从事软体机器人、布料仿真、触觉感知或灵巧操作的产品团队，MuJoCo 现在提供了比一年前更完整的工作流支持。建议评估系统辨识工具箱（3.5.0）和 DC 电机执行器（3.7.0）是否能替代当前使用的第三方工具。

- **未来路线图的关键信号包括：求解器多样化（Newton 和 PGS 求解器已在 3.3.3 中铺垫）、API 清理（3.10.0 明确提到未来破坏性变更）、以及 MJX 生态的持续扩展。** 产品经理应预期在下一个大版本中看到：旧 API 的集中移除、更多求解器选项、以及 MJX-Warp 后端的进一步成熟。建议在规划长期项目时，优先使用新 API 并避免依赖已弃用的功能。
