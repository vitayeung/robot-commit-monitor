# NVIDIA/warp Release Roadmap

- 仓库: `NVIDIA/warp`
- 统计窗口: 最近一年
- 最新版本: v1.15.0 (2026-07-08 06:40:23 CST)
- 纳入统计的最早版本: v1.8.1 (2025-08-02 01:41:44 CST)
- 版本概况: 最近一年共 13 个版本，其中正式版 12 个、预发布版 1 个
- 详细证据索引: `NVIDIA_warp_release_roadmap_reference.md`

## 核心判断

- **Warp 正在从纯 GPU 计算库演变为可移植的跨平台仿真运行时。** 过去一年，Warp 的核心能力从 CUDA 独占转向了 CPU 和 GPU 的对称支持，包括 CPU 图捕获与回放、可移植的 `.wrp` 序列化格式、以及跨进程和跨语言的图复用。这意味着用户现在可以在开发阶段使用 CPU 进行调试和迭代，然后无缝部署到 GPU 生产环境，而无需维护两套代码路径。

- **确定性执行和可重现性是仿真工作流的关键差异化功能。** v1.15 引入的确定性模式直接解决了仿真验证、回归测试和强化学习训练中的非确定性痛点。该功能允许用户在性能与可重现性之间进行权衡，支持同一 GPU 架构上的逐次一致性和跨 GPU 架构的保守一致性。对于需要精确复现结果的团队，这是一个重要的决策因素。

- **Warp 正在积极构建与 JAX 和 PyTorch 的深度互操作生态。** 从 v1.10 的 JAX 自动微分支持，到 v1.12 的 `jax.vmap` 兼容性，再到 v1.14 的稳定 JAX 集成 API，Warp 正在成为 JAX 生态中高性能物理仿真的首选后端。同时，RMM 分配器集成和纹理互操作 API 也强化了与 PyTorch 的协作能力。

- **API 清理和模块重构正在加速，迁移成本需要提前评估。** `warp.sim` 模块在 v1.10 被移除，Python 3.9 支持在 v1.13 被移除，内部 API 的转发垫片在 v1.13 被移除。这些变化表明 Warp 正在快速收敛到稳定的公共 API 表面，但用户需要关注每个版本的弃用公告，并计划相应的代码迁移。

## 产品演进主线

- **从 CUDA 独占走向跨平台可移植。** 过去一年，Warp 显著扩展了 CPU 后端的能力：v1.13 引入 CPU 图捕获和序列化，v1.14 将 CPU 捕获扩展到反向传播和 tiled 内核，v1.15 进一步支持 CPU 图回放和 CUDA 图保存。同时，`wp.bfloat16` 类型的加入和 `wp.MarchingCubes` 的纯 Warp 重写（v1.9）使得更多工作负载可以在 CPU 上运行。这条主线降低了硬件门槛，使开发者可以在没有 GPU 的环境中进行开发和测试。

- **仿真工作流的可重现性和确定性。** v1.15 的确定性执行模式是这一方向的核心交付物。它通过重写原子操作模式（累加、槽分配、输出映射）来保证位精确的可重现性。这对于强化学习训练、物理仿真验证、以及需要跨平台结果一致性的应用场景至关重要。该功能目前是实验性的，且不支持所有原子操作模式。

- **图捕获和序列化成为核心基础设施。** 从 v1.13 的实验性图序列化开始，Warp 在 v1.14 和 v1.15 持续扩展捕获能力：支持反向传播、tiled 内核、`@wp.struct` 参数、`wp.indexedarray` 参数、以及 CUDA 托管内存分配。`.wrp` 格式使得仿真图可以跨进程、跨语言（Python/C++）复用，为生产级部署提供了基础。

- **与 JAX 生态的深度集成。** v1.10 引入实验性 JAX 自动微分，v1.11 增加 `jax_callable` 的图模式支持，v1.12 支持 `jax.vmap`，v1.14 提供稳定的 JAX 集成 API。这条主线使 Warp 能够作为 JAX 工作流中的可微分物理引擎，服务于机器人学习、最优控制和科学计算等场景。

## 版本演进解读

### v1.15.0 (2026-07-08)

- **引入确定性执行模式**，支持 `RUN_TO_RUN`（同一 GPU 架构位精确）和 `GPU_TO_GPU`（跨 GPU 架构保守一致）两种模式。该功能通过重写支持的原子操作模式（累加、槽分配、输出映射）来实现可重现性。不支持 `wp.atomic_cas()`、`wp.atomic_exch()` 和 tile 原子操作。
- **扩展图捕获能力**：支持 CPU 图回放、保存的 CUDA 图、CUDA 托管内存分配和 mipmapped 纹理。`wp.ref[T]` 参数允许 Warp 函数直接修改调用者持有的存储，消除了返回-重新赋值的模式。
- **迁移注意**：确定性模式是实验性功能，API 可能在没有正式弃用周期的情况下更改。纹理 API 同样是实验性的。用户需要重新捕获 v1.14 及之前保存的 `.wrp` 文件。

### v1.14.0 (2026-06-01)

- **大幅扩展 CPU 图捕获范围**：现在支持 `wp.Tape().backward()` 的反向传播、`wp.launch_tiled()` 内核、任意大小的标量参数、包含数组的 `@wp.struct` 参数和 `wp.indexedarray` 参数。`.wrp` 文件格式升级到版本 10，不兼容 v1.13 保存的文件。
- **引入多环境 FEM 支持**，用于批处理仿真。可重用和可批处理的线性求解器、可插拔日志记录、可移植的 tile FFT 和求解器回退。
- **迁移注意**：APIC 句柄声明需要更新为显式指针（如 `APICState*`）。FEM 构造函数中 `requires_grad`、`device`、`temporary_store` 的位置参数签名已更改。

### v1.13.0 (2026-05-04)

- **引入实验性图捕获序列化和 CPU 回放**：操作记录到 `.wrp` 文件后，可以从 Python 或独立 C++ 加载并回放。新的 `wp.handle`（`uint64` 别名）支持跨保存/加载携带 `wp.Mesh` 句柄。
- **新增 cuBQL BVH 后端**，用于 `wp.Mesh` 的射线密集型查询。在 RTX 4090 上的基准测试显示，仿真时间从 1.41 秒降至 0.98 秒。新增 `wp.bfloat16` 标量类型。
- **可插拔 CUDA 分配器接口**，内置 RAPIDS Memory Manager (RMM) 集成，允许 Warp 与 PyTorch、CuPy 共享内存池。新增作用域内存跟踪，支持 C++ 层调用点归因。
- **重大清理**：移除私有 API 转发垫片（`warp.torch`、`warp.context` 等），代码直接访问这些路径将报错而非警告。纹理 `copy_from_array()` / `copy_to_array()` 方法已弃用。

### v1.12.1 (2026-04-06)

- **修复多个 tile 内核正确性问题**：包括跨设备使用错误 `block_dim`、`wp.tile_matmul()` 和 `wp.tile_fft()` 忽略模块级 `enable_backward`、以及 `@wp.func` 中 tile 参数编译失败。tile 参数现在按引用传递。
- **移除 Omniverse Kit 扩展**。新增可微分的 2D Navier-Stokes 优化示例和三个 `warp.fem` 示例。
- **宣布即将移除**：Python 3.9 支持将在 v1.13 移除。私有 API 弃用警告将在 v1.13 移除。

### v1.12.0 (2026-03-07)

- **引入实验性硬件加速纹理采样**：`wp.Texture1D`、`wp.Texture2D`、`wp.Texture3D` 利用 CUDA 纹理内存进行硬件加速插值。CPU 上提供软件回退，确保相同内核代码跨设备运行。
- **扩展 tile 编程**：新增逐元素算术运算符（`*`、`/`）、可微分的 FFT、以及 `tile_dot`、`tile_axpy`、`tile_stack` 等原语。新增下标风格类型提示，提升 IDE 集成体验。
- **JAX 互操作增强**：支持 `jax.vmap`。新增四元数和近似数学内置函数。`warp.fem` 新增 B 样条形函数。
- **弃用**：Python 3.9 支持、标量到复合类型的隐式转换、以及 `warp.fem` 中 `interpolate()` 的 `quadrature` 和 `domain` 参数。

### v1.11.1 (2026-02-04)

- **修复多个关键 bug**：`wp.tile_matmul()` 在特定形式下产生 NaN、CUDA 图中多个临时分配导致内存过度使用（例如三个 1GB 分配消耗 3GB 而非复用）、`wp.static()` 在循环展开中错误捕获全局变量。
- **开发者体验改进**：修复 `@wp.func` 在 Pyright/Pylance 中显示泛型 `_Wrapped` 类型的问题。修复 IDE 自动补全存根中的多个类型检查错误。

### v1.11.0 (2026-01-02)

- **引入组感知空间查询**：`wp.Bvh` 和 `wp.Mesh` 支持 `groups` 参数，允许在单一加速结构中包含多个独立环境，并独立查询每个环境。适用于多世界仿真和并行射线投射。
- **JIT 编译管理新选项**：`wp.force_load()` 提供更细粒度的模块编译控制。支持预编译头文件（PCH）加速 CUDA 编译。支持并行模块编译和加载。
- **API 边界清理**：内部 API 访问现在发出弃用警告，将在 v1.13 移除。文档重组，明确区分公共 API 和内部实现。新增 `wp.grad()` 用于直接梯度计算。

### v1.10.1 (2025-12-01)

- **修复多个 bug**：`module="unique"` 内核的模块复用、内核本地数组的 `.ptr` 访问和索引、自定义梯度函数的代码生成排序问题、FEM 中 `TemporaryStore` 的无效读取。
- **弃用**：`jax_callable()` 的 `graph_compatible` 参数，替换为 `graph_mode` 枚举参数。
- **平台变更预告**：Python 3.8 支持将在 v1.11 移除。PyPI 预构建 wheel 将从 CUDA 12.8 切换到 12.9。

### v1.10.0 (2025-11-02)

- **移除 `warp.sim` 模块**：该模块已被 Newton 物理引擎取代。内部实现代码重组到 `warp._src` 子包中，以明确公共 API 边界。
- **JAX 自动微分（实验性）**：支持通过 `jax.grad()` 计算 Warp 内核的梯度。支持单输出和多输出内核、静态输入自动检测、以及 `jax.pmap()` 多设备兼容性。
- **性能大幅提升**：Python 作用域内置函数调用速度提升最高 70 倍。BVH 操作支持 CUDA 图中的原地重建和可配置叶子大小。新增负索引和切片、原子位操作、误差函数等。
- **迁移注意**：不再支持向内置函数传递列表、元组等非 Warp 数组参数。`wp.Bvh` 默认 `leaf_size` 从 4 改为 1。

### v1.9.1 (2025-10-01)

- **恢复对旧 GPU 架构的支持**：Maxwell、Pascal、Volta 架构在 v1.9.0 的 PyPI wheel 中被意外移除，现已恢复。
- **修复共享 tile 的内存管理问题**：防止不可预测的崩溃和内存泄漏。`wp.copy()` 和 `wp.where()` 现在支持 tile 并计算正确的梯度。
- **已知限制**：Linux ARM 系统（如 Jetson Thor、Grace Hopper）上的 CPU 内核可能发生段错误，计划在 v1.10 修复。

### v1.9.0 (2025-09-05)

- **可微分的 Marching Cubes**：完全用 Warp 重写，替代了之前的原生 CUDA C++ 实现，现在可在 CPU 和 GPU 上运行。修复了长期存在的 off-by-one bug。
- **AOT 编译工作流增强**：新增 `wp.compile_aot_module()` 和 `wp.load_aot_module()`，支持 `strip_hash=True` 参数以分发预编译模块而不需要原始 Python 源代码。
- **CUDA 13 支持**：PyPI wheel 将继续使用 CUDA 12.8 构建以提供过渡期。图可捕获的线性求解器（CG、BiCGSTAB、GMRES）支持设备端收敛检查。

### v1.8.1 (2025-08-02)

- **最终支持 CUDA 11.x 的版本**：从 v1.9.0 开始，Warp 将要求 CUDA 12.x 或更新版本。
- **JAX 实验模块增强**：支持 `jax_callable()` 的输入-输出别名、以及通过 `GraphMode.WARP` 捕获包含条件节点的图。弃用 `graph_compatible` 布尔标志，替换为 `graph_mode` 枚举。
- **修复**：`tape.zero()` 在嵌套结构体中正确重置梯度数组、CUDA 模块在条件图节点中使用时被过早卸载、以及使用 matmul/Cholesky/FFT 求解器的内核编译时间回归。

## 采用与规划提示

- **采用时机**：如果您的团队需要可重现的仿真结果（如强化学习训练、回归测试），v1.15 的确定性执行模式是值得评估的关键功能。但请注意该功能目前是实验性的，且不支持所有原子操作模式。建议先在非关键路径上验证性能影响。

- **迁移成本**：过去一年 Warp 进行了大规模的 API 清理和模块重构。如果您的代码仍在使用 `warp.sim`、内部 API（如 `warp._src`）、或已弃用的函数签名，需要立即规划迁移。建议关注每个版本的弃用公告，并在升级前运行完整的测试套件。`.wrp` 文件格式在 v1.14 有破坏性变更，需要重新捕获。

- **目标用户**：Warp 正在从物理仿真库演变为可微分的跨平台计算框架。当前最适合的用户包括：需要可微分物理的机器人学习团队、需要高性能仿真且希望与 JAX/PyTorch 生态集成的团队、以及需要跨平台（CPU/GPU）部署能力的仿真应用开发者。

- **生态观察点**：Warp 与 JAX 的集成正在快速成熟，v1.14 提供了稳定的 JAX 集成 API。同时，RMM 分配器集成使得与 PyTorch 共享 GPU 内存成为可能。建议关注 Newton 物理引擎的进展，它已取代 `warp.sim` 成为 Warp 生态中的物理仿真层。CUDA 13 的支持已就绪，但默认 wheel 仍使用 CUDA 12.8 构建。

- **下一步路线图方向**：基于过去一年的演进模式，预计 Warp 将继续扩展图捕获和序列化的覆盖范围（包括更多操作类型和硬件后端），深化与 JAX 的自动微分集成，并可能推出更成熟的 AOT 编译工作流。确定性执行模式可能会从实验性转为正式功能，并扩展支持的原子操作模式。
