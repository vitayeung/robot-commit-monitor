# google-deepmind/mujoco Release Roadmap

- 仓库: `google-deepmind/mujoco`
- 统计窗口: 最近一年
- 最新版本: 3.10.0 (2026-06-23 01:04:32 CST)
- 纳入统计的最早版本: 3.3.4 (2025-07-10 04:14:25 CST)
- 版本概况: 最近一年共 12 个版本，其中正式版 12 个、预发布版 0 个
- 详细证据索引: `google-deepmind_mujoco_release_roadmap_reference.md`

## 核心判断

- **MuJoCo 在过去一年中从物理仿真引擎加速演变为一个面向机器人学和可变形体仿真的全栈平台。** 新增了系统辨识工具箱、DC 电机执行器、柔性体（flex）的隐式积分和高级碰撞支持，以及 MJX 的 Warp 后端。这些变化显著扩展了产品在机器人控制、布料仿真和接触丰富的操作任务中的适用性。

- **产品路线图明确指向更高的仿真保真度、更广的生态系统覆盖以及 API 的现代化。** 关键信号包括：引入精确的对角惯性矩阵计算（`diagexact`）、CG 求解器的 Hager-Zhang 更新、以及将布尔类型从 `mjtByte` 迁移到 `mjtBool`。这些改进提升了数值精度和代码清晰度，但同时也带来了迁移成本。

- **MJX（基于 JAX 的加速后端）正在经历重大重构，Warp 成为新的首选后端。** 从 3.3.5 版本开始，Warp 作为 MJX 的后端实现被引入，并在后续版本中持续获得大量代码投入（如批渲染、碰撞检测、求解器优化）。这表明团队正在将 MJX 从实验性功能推向生产级产品，但用户可能需要关注后端迁移的兼容性。

- **API 稳定性和向前兼容性是持续关注点，但存在明确的弃用和迁移路径。** 多个版本引入了弃用警告（如 `mju_user_error` 回调、`mjs_isWarning`、旧式 `mj_fullM` 签名），并提供了清晰的迁移指南。产品经理应规划在下一个 LTS 版本前完成这些 API 迁移。

## 产品演进主线

- **可变形体（Flex）仿真能力从基础支持走向成熟。** 过去一年中，flex 组件获得了隐式积分（3.5.0）、二次型自由度（3.4.0）、多单元支持（3.8.0）、与 SDF 几何体的碰撞（3.6.0）、以及弹性 2D 支持（3.8.1）。这使得 MuJoCo 能够处理更复杂的布料、软体机器人等用例，从简单的刚体仿真扩展到连续介质力学。

- **求解器与数值精度持续优化，面向高保真度仿真。** 3.9.0 版本引入了 `diagexact` 标志以精确计算约束空间惯性矩阵，3.10.0 版本将 CG 求解器的共轭方向更新从 Polak-Ribiere-Plus 改为 Hager-Zhang 公式，并改进了 float32 下的收敛性。这些变化直接提升了仿真稳定性，尤其适用于具有各向异性惯性或复杂运动学耦合的模型。

- **传感器和执行器生态大幅扩展，支持更丰富的机器人感知与控制。** 新增了触觉传感器（tactile sensor，3.3.5）、接触传感器（contact sensor，3.3.5）、内部站点传感器（inside site sensor，3.3.5）、DC 电机执行器（3.7.0）、以及执行器和传感器的任意延迟支持（3.5.0）。这些功能使 MuJoCo 能够更真实地模拟机器人硬件，减少 sim-to-real 差距。

- **Python 生态系统和工具链显著增强，降低用户门槛。** 新增了系统辨识工具箱（3.5.0）、Python 虚拟文件系统绑定（3.8.1）、编译器设置查询 API（3.6.0）、以及改进的 MJCF 模式文档。同时，Python 3.14 支持在 3.8.0 版本中加入。这些变化使 MuJoCo 对 Python 用户更加友好，便于集成到现代机器学习工作流中。

## 版本演进解读

### 3.10.0 (2026-06-23)

- **求解器性能重大提升：** CG 求解器改用 Hager-Zhang 共轭方向更新，替代 Polak-Ribiere-Plus 公式。这显著改善了 float32 下的收敛速度和求解质量。同时，原始求解器在 float32 下的收敛性也得到了改进。
- **新的线程池 API 和日志系统：** 新增 `mju_threadpool` 函数用于设置引擎的工作线程数，替代了旧的引擎线程 API。新增统一的日志 API，并提供了 `mjs_numWarnings` 和 `mjs_getWarning` 用于检索编译警告。旧的 `mju_user_error` 和 `mju_user_warning` 回调已被弃用。
- **模型编译与兼容性改进：** 新增 `compiler/conflict` 属性以控制全局属性冲突的处理策略（未来默认策略将改为“merge”）。新增 `mjs_makeFlex` C API 函数，支持从 OBJ 线段加载 1D flex 组件。改进了 `maxhullvert` 属性生成的凸包质量。`mj_fullM` 函数签名已更改，需要迁移。

### 3.9.0 (2026-05-27)

- **精确约束空间惯性矩阵：** 新增 `diagexact` 启用标志，可在当前配置下精确计算约束空间惯性矩阵的对角线，替代默认的编译时近似。这显著改善了具有各向异性惯性或复杂运动学耦合的模型的求解器质量。
- **编译器计时诊断和类型系统现代化：** 新增 `mjtCTimer` 枚举和 `mjs_getTimer` C API，可在编译后获取按类别划分的计时信息（总时间、资产、网格加载、凸包等）。新增 `mjtBool` 类型替代 `mjtByte`，用于 `mjModel`、`mjData` 和公共 C API 中的所有布尔字段。这提高了代码清晰度和类型安全性。
- **触觉传感器行为变更：** 触觉传感器现在报告原始深度而非估计压力。这改变了传感器输出语义，用户需要调整依赖压力值的下游处理逻辑。

### 3.8.1 (2026-05-11)

- **PGS 求解器获得岛支持：** PGS 求解器现在支持岛（island）处理，并以伪随机顺序迭代约束，提高了性能。这扩展了岛求解器的覆盖范围，此前仅 CG 求解器支持。
- **flex 和 spec API 增强：** 新增对三线性和二次型 flex 自由度的 `elastic2d` 支持。新增 `mjs_getOriginSpec` 函数，可返回元素在附加前最初定义的 spec。新增 `mju_sym2dense` 函数，用于将下三角隐式对称 CSR 矩阵转换为稠密对称矩阵。
- **Python 虚拟文件系统绑定：** 新增 Python 绑定，允许直接从 Python 与虚拟文件系统交互。这简化了在 Python 环境中管理模型资产的工作流。

### 3.8.0 (2026-04-25)

- **Python 3.14 支持和 flex 多单元能力：** 正式支持 Python 3.14。三线性和二次型 flex 现在支持多单元（multi-cell），但隐式积分器对 flex 自由度使用稠密求解器，多单元 flex 可能较慢。
- **碰撞检测改进：** 新的碰撞管线现在默认启用，相比旧管线性能开销小且稳定性更高。新增 `mj_maxContact` 函数以获取可能的最大接触数。
- **URDF 解析和插件注册变更：** URDF 解析不再硬编码 `strippath` 为“true”，现在尊重该设置。`mjPLUGIN_LIB_INIT` 宏现在需要名称参数以避免初始化函数名称冲突。`mjsFlex` 中的 `collision` 字段已被移除，因为 MuJoCo Warp 已原生支持 flex 碰撞。

### 3.7.0 (2026-04-14)

- **DC 电机执行器：** 新增 `dcmotor` 执行器，用于建模直流电机。支持可选的反射阻尼和惯性（通过 `gear^2` 缩放），在被动力和惯性计算中应用。这为机器人仿真提供了更真实的电机模型。
- **非线性和多项式力轮廓：** 关节和肌腱的刚度和阻尼现在支持非线性多项式力轮廓。多项式阶数由新常量 `mjNPOLY` 定义，未来 C API 将发生破坏性变更。
- **约束求解器精度提升：** 为 `connect` 和 `weld` 等式约束添加了科里奥利加速度项，显著提高了这些约束的精度。新增了独立自由体的中点积分。

### 3.6.0 (2026-03-10)

- **编译器设置查询和 flex-SDF 碰撞：** 新增 `mjs_getCompiler` C API 函数和所有 Python spec 元素类型的只读属性，允许在编译后查询编译器设置。Flex 现在支持与 SDF 几何体的碰撞。
- **MJX-Warp 批渲染和内存改进：** 新增 MJX-Warp 批渲染支持。改进了 `mjModel` 的内存需求，分配大小现在使用 64 位整数以支持更大场景。
- **API 破坏性变更：** 射线投射函数现在可选计算表面法线，这是一个破坏性变更。相机 MJCF 属性已重命名为 `camera/projection`。`mj_stateSize` 及相关函数的 `signature` 参数类型已更改。

### 3.5.0 (2026-02-13)

- **系统辨识工具箱：** 新增 Python 系统辨识工具箱，用于从数据中识别模型参数。这为机器人学和控制领域的用户提供了强大的模型校准能力。
- **执行器和传感器延迟支持：** 执行器和传感器现在支持通过历史缓冲区实现任意延迟，传感器值可以在任意时间点计算。这对于模拟通信延迟或传感器处理延迟至关重要。
- **柔性体隐式积分和 flexvert 约束：** 新增对可变形对象（flex）的隐式积分支持。新增 `flexvert` 等式约束类型，支持使用更粗网格进行布料仿真。

### 3.4.0 (2025-12-05)

- **二次型 flex 和 Windows 栈大小增加：** Flex 组件新增“quadratic”自由度选项，包含弯曲变形。Windows 栈大小增加到 16MB，以支持具有深层嵌套身体层次结构的模型。
- **新的管线组件和状态管理：** 新增 `mj_fwdKinematics` 函数，组合所有运动学子组件。新增 `mj_copyState` 函数用于复制状态组件。肌腱路径现在可以从 Python 查询。
- **MJX 和渲染更新：** `OpenUSD` 可选依赖更新到 1.10.0。MJX 现在支持 MuJoCo Warp。旧的 Madrona MJX 代码路径不再受支持，用户将迁移到基于 Warp 的批渲染器。

### 3.3.7 (2025-10-15)

- **Spec API 字段迁移：** `mjSpec` C API 中的 `meshdir` 和 `texturedir` 字段已移至 `compiler.meshdir` 和 `compiler.texturedir`。Python API 中旧字段仍可用但将在未来版本中移除。
- **资产依赖计算和 C++ 标准提升：** 新增 `mju_getXMLDependencies` 函数，用于计算 MJCF 文件的唯一资产依赖列表。最低 C++ 标准提升至 C++20。
- **Bug 修复：** 修复了 `fitaabb` 为网格添加偏移量并应用错误帧的问题。

### 3.3.6 (2025-09-15)

- **求解器状态更新和 idempotent 行为：** 约束求解器的状态更新从 `mj_fwdConstraint` 末尾移至 `mj_step` 末尾，使 `mj_forward` 完全幂等。这改变了 RK4 积分器的数值行为，使其积分更加原理正确，但可能影响依赖旧行为的用户。
- **被动力禁用标志重构：** 旧的 `mjDSBL_PASSIVE` 标志被移除，替换为 `mjDSBL_SPRING` 和 `mjDSBL_DAMPER`，分别禁用关节和肌腱的弹簧和阻尼力。
- **接触传感器和 flex 增强：** 接触传感器的 `subtree1/subtree2` 规范现在可用于任何身体。新增了对具有弯曲参考配置的壳体的支持。新增了 flex 被动接触的实验性选项。

### 3.3.5 (2025-08-09)

- **新型传感器系列：** 新增 `inside site` 传感器（检查对象是否在站点体积内）、`contact` 传感器（按用户定义报告接触信息）、以及 `tactile` 传感器（测量穿透深度和滑动速度）。这些传感器为触觉反馈和接触丰富的操作任务提供了原生支持。
- **SDF 原生支持和内置网格：** 移除了 SdfLib 插件及其依赖，SDF 现在在 `mjModel` 中原生支持。新增了创建内置网格的功能（`mesh/builtin`）。
- **MJX Warp 后端：** 正式引入 Warp 作为 MJX 的后端实现，可通过配置指定。Linux wheels 现在基于 manylinux 2.28（之前是 CentOS 7）。

### 3.3.4 (2025-07-10)

- **查看器和 spec API 改进：** 新增通过 `visual/global/cameraid` 设置查看器初始相机的支持。Python 被动查看器新增仅同步状态的选项以提高性能。`mjs_setString` 被 `mjs_setName` 替代，可在设置时检查命名冲突。
- **文档和迁移说明：** 补充了缺失的文档，并澄清了 3.3.3 版本中破坏性变更的性质。`fuse static` 的限制已被移除，现在可用于包含引用的模型。

## 采用与规划提示

- **建议在下一个主要版本（3.11.0）发布前完成 API 迁移。** 多个弃用路径（如 `mju_user_error` 回调、旧式 `mj_fullM` 签名、`mjs_isWarning`）将在未来版本中移除。产品团队应审计代码库中这些 API 的使用情况，并按照官方迁移指南进行更新。迁移成本中等，但提前规划可避免紧急升级。

- **对于机器人学和 sim-to-real 应用，3.10.0 版本是当前最推荐的生产版本。** 该版本在求解器精度、线程管理、模型编译和传感器生态方面提供了最全面的能力。特别是 DC 电机执行器、系统辨识工具箱和新的传感器系列，直接降低了从仿真到真实机器人的迁移难度。

- **关注 MJX 的 Warp 后端迁移进度。** 如果团队依赖 MJX 进行大规模并行仿真，应密切关注 Warp 后端的成熟度。当前 Warp 后端正在快速迭代（批渲染、碰撞检测、求解器），但旧版 Madrona 后端已被弃用。建议在 Warp 后端达到稳定状态后再进行生产级迁移。

- **可变形体（flex）仿真能力已足够成熟，可用于产品原型设计。** 从 3.5.0 版本开始的隐式积分、3.8.0 版本的多单元支持、以及 3.8.1 版本的弹性 2D 支持，使 flex 组件能够处理从简单布料到复杂软体机器人的多种用例。但需注意多单元 flex 的隐式积分可能较慢，建议在性能敏感场景中进行基准测试。
