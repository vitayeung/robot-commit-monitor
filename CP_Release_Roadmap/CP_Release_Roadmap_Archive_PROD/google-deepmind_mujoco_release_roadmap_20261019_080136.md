# google-deepmind/mujoco Release Roadmap

- 仓库: `google-deepmind/mujoco`
- 统计窗口: 最近一年
- 最新版本: 3.15.0 (2026-10-05 22:58:18 CST)
- 纳入统计的最早版本: 3.3.7 (2025-10-15 01:38:32 CST)
- 版本概况: 最近一年共 14 个版本，其中正式版 14 个、预发布版 0 个
- 详细证据索引: `google-deepmind_mujoco_release_roadmap_reference.md`

## 核心判断

- **3.15.0 修正了 `dampratio` 的反射惯量计算方式，属于破坏性 API 变更。** 现在在 `mjModel.qpos0` 处以操作空间惯量 $(J M^{-1} J^T)^{-1}$ 计算反射惯量，并计入肌腱与执行器 armature 以及非对角惯量耦合，替代原先按自由度求和 $\text{dof\_M0}_j / J_j^2$ 的做法。多连杆运动链上使用 `dampratio` 的执行器阻尼会低于此前，而驱动跨多关节肌腱或站点的执行器阻尼会更准确。

- **3.15.0 集中修复 `.mjz` 归档的跨平台与路径解析问题。** Windows 上写出的 `.mjz` 归档现在始终使用 `/` 分隔符；`meshdir`/`texturedir` 中的资产在归档被重写、目录路径为绝对路径、使用 `..` 或使用 URI scheme 时均可正确解析。这延续了 3.14.0 归档资源提供者与 3.13.0 固定根文件名的归档治理方向。

- **3.15.0 的引擎与 MJX/Warp 后端继续同步演进。** 碰撞驱动、核心工具与导数模块有改动，MJX-Warp 的渲染与平滑模块同步更新，GPU 加速路径的渲染与柔性体行为持续变化。

- **3.14.0 确立的 `ipc` 柔性体接触与归档资源提供者仍是当前能力基线。** 3.15.0 未改变 `ipc` 的实验性定位与状态限制，也未改变归档资源提供者的接口形态，而是在归档路径正确性上做补强。

## 产品演进主线

- **引擎数值能力在 3.14.0 的 `ipc` 无穿透柔性体接触之后，转向执行器阻尼建模的精度修正。** 3.15.0 的 `dampratio` 反射惯量改为操作空间惯量并计入 armature 与非对角耦合，延续了从 3.13.0 `discrete` 积分器以来对求解器与执行器数值质量的投入。

- **模型资产打包与装载从"可插拔资源提供者"走向"跨平台路径正确性"。** 3.13.0 固定 `.mjz` 根文件名为 `model.xml`，3.14.0 引入归档资源提供者解耦容器与解码器，3.15.0 修复 Windows 分隔符与 `meshdir`/`texturedir` 在重写、绝对路径、`..`、URI scheme 下的解析，归档工程化治理继续深化。

- **MJX/Warp 后端与原生引擎的同步演进节奏保持稳定。** 3.12.0 至 3.15.0 中 MJX 的求解器、碰撞、IO、渲染模块持续改动，GPU 加速路径仍作为第一等公民演进。

- **感知与可视化能力在 3.14.0 的 Filament 渲染实现之后进入稳定期。** 3.15.0 未新增渲染或感知特性，重点转向归档与执行器数值修正。

## 版本演进解读

### 3.15.0（2026-10-05）

- 破坏性变更：`dampratio` 的反射惯量改为在 `mjModel.qpos0` 处以操作空间惯量 $(J M^{-1} J^T)^{-1}$ 计算（多输出执行器如 `orientation` 在力输出间取平均），替代按自由度求和 $\text{dof\_M0}_j / J_j^2$，并计入肌腱与执行器 armature 及非对角惯量耦合。多连杆运动链上使用 `dampratio` 的执行器阻尼会低于此前，驱动跨多关节肌腱或站点的执行器阻尼会更准确，并避免多自由度传动在雅可比项很小时出现极端阻尼值。
- `.mjz` 归档在 Windows 上写出现在始终使用 `/` 分隔符；`meshdir`/`texturedir` 中的资产在归档被重写、目录路径为绝对路径、使用 `..` 或使用 URI scheme 时均可正确解析。跨平台分发归档或使用绝对路径、`..`、URI scheme 引用资产的用户需重新验证装载结果。
- 引擎碰撞驱动、核心工具与导数模块有改动，MJX-Warp 的渲染与平滑模块同步更新。使用 `dampratio` 的模型与 MJX/Warp 用户应在升级后对关键场景做数值回归。

### 3.14.0（2026-09-23）

- 新增实验性 `ipc` 标志，作为 `discrete` 积分器的接触模式，用于无穿透柔性体接触：每步在满足线性化接触约束的前提下最小化增量势能，采用无势垒增广拉格朗日法，子问题即 `discrete` 求解；每次提交的位置更新经连续碰撞检测验证无交叠，柔性体接触不会穿透。目前支持 dim-2 flex，解析的接触为无摩擦接触。
- 该模式的接触乘子跨步保留且不被任何状态规范覆盖，`mj_getState`/`mj_setState` 无法捕获其完整状态，不支持精确重放。需要状态快照或确定性重放的柔性体仿真流程需评估这一限制。
- 新增归档资源提供者 `mjp_registerArchiveResourceProvider`，使用 `mjpResourceProvider` 接口挂载和读取归档容器（如 `.mjz`/`.zip`），将容器处理与格式解码器解耦，并支持按需提取资产而无需预分配 VFS。依赖自定义归档容器或 VFS 预分配的工具链可据此调整装载方式。

### 3.13.0（2026-09-09）

- 新增 `discrete` 积分器，将约束求解与隐式速度更新合并为在有效度量 $\widehat{M} = M + hD + h^2K$ 上的单次操作，关节、肌腱和执行器的刚度与阻尼并入求解器度量，被动弹簧和执行器位置增益在远超显式稳定极限的步长下保持稳定；`mjData.qacc` 在该积分器下为离散步映射 $(v^+ - v)/h$。这对需要大步长实时仿真的用户价值显著，但会改变现有模型的数值行为，需回归验证。
- 站点几何体新增网格类型支持（`type="mesh"` 配合 `mesh="name"`），可用于可视化、`insidesite` 传感器和新增的 `mj_insideSite` 函数。这扩展了站点在感知与可视化中的用途，现有仅使用基本几何类型的模型不受影响。
- 新增 Python 3.15 支持（含 GIL 与 Free-Threading）；`.mjz` 归档编码器将根文件固定写为 `model.xml`，降低因文件重命名导致的归档损坏风险。使用 `.mjz` 归档的用户需注意根文件名的变化。

### 3.12.0（2026-08-20）

- 新增原生 `pid` 执行器，支持位置和速度设定点输入、可选积分项（`ki`，含 `imax` 抗饱和）、设定点速率限制（`slewmax`）和前馈输入。它取代 `mujoco.pid` 插件，并在所有积分器下具有正确的激活状态，对关键帧和传感器可见。使用旧插件的用户应迁移到原生执行器。
- MJCF 语法现在由单一 schema 文件 `src/xml/mjcf.schema` 定义，解析器的语法表、存在性约束、关键字映射、类型化属性绑定和保存策略均由其生成并有测试门禁。这减少了语法定义与文档、C 头文件之间的不一致风险。
- 破坏性变更：自定义二进制纹理格式（`image/vnd.mujoco.texture`）被移除，加载未识别扩展名文件时不再自动回退到自定义纹理。纹理仅支持 PNG 和 KTX 格式。使用自定义纹理的模型需转换资源格式。
- MJX/Warp 后端的求解器、约束处理和 IO 模块有大规模改动，并新增 flex 布料示例模型。MJX 用户应验证现有模型在新版本下的数值行为。

### 3.11.0（2026-07-28）

- 新增 `geom/surfacevel` 属性，可为几何体定义表面速度场（含恒定分量和绕几何体原点的旋转分量），用于模拟传送带、跑步机和转盘等运动表面。静态几何体即可驱动接触物体运动，无需额外自由度，显著简化了这类场景的建模复杂度。
- 新增 `geom/adhesion` 和 `pair/adhesion` 属性，为接触添加粘附力，接触可承受最大拉力并在超过后断裂，摩擦预算变为 μ(f_N + adhesion)。结合 `gap` 属性可模拟粘性材料，适用于抓取、粘附等应用。注意 `mjData.efc_vel` 和约束状态传感器报告的是相对运动表面的速度而非相对几何体的速度。
- MJX-Warp 后端的约束求解器、柔性体碰撞和导数计算模块有大规模更新，表明新接触特性在 GPU 加速路径上同步支持。使用 MJX 的用户应验证自定义模型在新版本下的数值行为。

### 3.10.0 (2026-06-23)

- 新增统一日志 API，并废弃旧回调 `mju_user_error` 和 `mju_user_warning`，但仍保持功能兼容。用户应开始迁移到新 API，以避免未来版本中断。
- CG 求解器采用 Hager-Zhang 共轭方向更新，替代 Polak-Ribiere-Plus 公式，在 float32 下显著提升收敛速度和精度。这对在 GPU 上运行仿真的用户尤其重要。
- 新增 `mju_threadpool` 函数用于创建线程池，旧引擎线程 API 被移除。用户需迁移到新线程池接口以控制工作线程数量。
- 新增 `mjs_makeFlex` C API 函数（等价于 `flexcomp` 元素），并支持从 OBJ 线段加载 1D flex 组件。这简化了可变形体的程序化创建流程。

### 3.9.0 (2026-05-27)

- 新增 `diagexact` 标志，可在当前配置下计算精确的约束空间惯量矩阵对角线，替代默认的编译时近似。这对具有各向异性惯量或复杂运动学耦合的模型显著提升求解器质量。
- 引入 `mjtBool` 类型替代 `mjtByte`，覆盖 `mjModel`、`mjData` 和公共 C API 中的所有布尔字段。大多数模型无需修改，但使用 `efc_address=-1` 的模型需要调整。
- 新增编译器计时诊断 API（`mjtCTimer` 枚举和 `mjs_getTimer` C API），编译后可输出按类别（总时间、资源、网格加载、凸包等）的耗时统计。这帮助用户识别编译瓶颈。
- 触觉传感器现在报告原始深度而非估计压力。使用该传感器的用户需调整后处理逻辑。

### 3.8.1 (2026-05-11)

- PGS 求解器获得岛支持，并以伪随机顺序迭代约束，提升性能。这改善了使用 PGS 求解器的模型的收敛速度。
- 新增 `mjs_getOriginSpec` 函数，返回元素在附件前的原始定义来源。这有助于调试复杂的模型组合场景。
- 新增 `mju_sym2dense` 函数，将下三角隐式对称 CSR 矩阵转换为稠密对称矩阵。这是为未来移除旧格式 `mj_fullM` 做准备。

### 3.8.0 (2026-04-25)

- 新增 Python 3.14 支持，确保与最新 Python 生态兼容。
- 为三线性和二次型 flex 添加多单元支持。注意隐式积分器对 flex 自由度使用稠密求解器，多单元 flex 可能较慢。
- 新增 `mj_maxContact` 函数，用于获取 `mj_contact` 可能返回的最大接触数。这帮助用户预分配缓冲区。
- 新的碰撞管线默认启用，相比旧管线性能开销小且稳定性更好。

### 3.7.0 (2026-04-14)

- 新增 `dcmotor` 执行器，用于建模 DC 电机，支持可选的反射阻尼和惯量（通过 `gear2` 缩放）。这对机器人关节的精确建模至关重要。
- 关节和肌腱的刚度/阻尼现在支持非线性多项式力曲线，由新常量 `mjNPOLY` 定义阶数。未来 C API 将为此进行破坏性变更。
- 为 `connect` 和 `weld` 等式约束添加向心/科里奥利加速度项，显著提升高速运动下的约束精度。
- `mjsFlex` 中的 `collision` 字段被移除，因为 MuJoCo Warp 已原生支持 flex 碰撞。用户需更新模型定义。

### 3.6.0 (2026-03-11)

- 新增 `mjs_getCompiler` C API 函数和 Python spec 元素的只读 `compiler` 属性，允许在附件后查询编译器设置。这增强了模型构建的可追溯性。
- Flex 现在支持与 SDF 几何体碰撞，扩展了可变形体的交互范围。
- 新增 MJX-Warp 批量渲染支持，适合大规模场景的离线渲染。
- 修复了 `mjs_attach` 静默丢弃带包裹几何体的空间肌腱的 bug（issue #3119）。用户需检查现有模型是否受影响。

### 3.5.0 (2026-02-13)

- 新增系统辨识工具箱（Python），用于从数据中辨识模型参数。这对机器人学用户进行模型校准非常实用。
- 执行器和传感器现在支持任意延迟（通过历史缓冲区），传感器值可在任意时间点计算。这使仿真更接近真实硬件的时间行为。
- 新增 `flexvert` 等式约束，允许使用较粗网格进行布料仿真（基于 Chen, Kry and Vouga 2019 方法）。这降低了布料仿真的计算成本。
- 射线投射函数现在可选计算表面法线，这是一个破坏性变更（新增参数）。Python 中除 `mj_multiRay` 外默认计算法线。

### 3.4.0 (2025-12-06)

- 为 `flexcomp/dof` 新增 "quadratic" 选项，在 "trilinear" 基础上增加弯曲变形能力。这提升了可变形体的仿真保真度。
- Windows 栈大小增至 16MB，以支持深层嵌套 body 层次结构的模型。这对复杂机器人模型用户是重要的兼容性修复。
- 新增 `mj_fwdKinematics` 管线组件函数，整合所有运动学子组件。同时新增 `mj_copyState` 函数用于复制状态组件。
- 肌腱路径现在可从 Python 查询，简化了肌腱系统的调试和可视化。

### 3.3.7 (2025-10-15)

- `mjSpec` C API 中的 `meshdir` 和 `texturedir` 字段移至 `compiler.meshdir` 和 `compiler.texturedir`。Python API 中旧字段仍可用但将在未来版本移除。
- 新增 `mju_getXMLDependencies` 函数，用于计算 MJCF 文件的唯一资源依赖列表。这有助于资产管理和部署。
- 最低 C++ 标准提升至 C++20，与 Google 内部标准对齐。使用旧编译器的用户需升级。

### 3.3.6 (2025-09-16)

- 接触传感器 `subtree1`/`subtree2` 规范现在可用于任意 body，不再限于根 body。这增加了接触检测的灵活性。
- 约束求解器收敛状态更新从 `mj_fwdConstraint` 末尾移至 `mj_step` 末尾，使 `mj_forward` 完全幂等。这改变了 RK4 积分器的数值行为，使其更符合物理原理。
- 禁用被动力的标志被移除，替换为 `mjDSBL_SPRING` 和 `mjDSBL_DAMPER`，分别禁用关节和肌腱的弹簧/阻尼力。用户需更新代码。

### 3.3.5 (2025-08-09)

- 新增 `insidesite`、`contact` 和 `tactile` 三种传感器，分别用于检测物体是否在站点内、报告接触信息、以及测量穿透深度和滑动速度。这显著增强了触觉和接触感知能力。
- 移除 SdfLib 插件及其依赖，SDF 现在原生支持于 `mjModel` 中。这简化了部署并提升了性能。
- 新增内置网格创建功能（`mesh/builtin`），允许在 XML 中直接定义简单几何体。
- 新增 `mj_makeM` 函数，结合 CRB 算法和肌腱 armature 项，替代 `mj_crb` 用于惯量计算。用户应迁移到新函数。

### 3.3.4 (2025-07-10)

- 新增通过 `visual/global/cameraid` 设置查看器初始相机的支持，改善了可视化体验。
- Python passive 查看器新增仅同步状态的选项，默认行为不变（复制整个模型和数据）。这在大场景中可提升性能。
- `mjSpec` C API 中，`mjs_setString` 被 `mjs_setName` 替代，可在设置时检查命名冲突而非编译时。这提升了模型构建的健壮性。

## 采用与规划提示

- **建议新项目基于 3.15.0 启动。** 该版本在 3.14.0 的 `ipc` 柔性体接触与归档资源提供者基础上，修正了 `dampratio` 反射惯量并修复 `.mjz` 跨平台路径解析。现有项目迁移需重点评估 `dampratio` 变更对执行器阻尼的影响。

- **使用 `dampratio` 的执行器需在升级后重新校验阻尼行为。** 多连杆运动链上的执行器阻尼会低于此前，驱动跨多关节肌腱或站点的执行器阻尼会更准确。建议对依赖 `dampratio` 的关节与传动逐一回归，确认控制性能符合预期。

- **跨平台分发 `.mjz` 归档或使用绝对路径、`..`、URI scheme 引用资产的用户需关注 3.15.0 的路径修复。** Windows 上写出的归档现在统一使用 `/` 分隔符，`meshdir`/`texturedir` 在归档重写与特殊路径形式下均可正确解析，依赖旧分隔符或旧解析行为的工具链需同步调整。

- **MJX/Warp 用户应关注 3.15.0 中的后端改动。** 渲染与平滑模块有更新，建议在升级后对关键仿真与渲染场景进行回归验证。
